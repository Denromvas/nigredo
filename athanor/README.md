# Атанор — нативний виконавець Nigredo

*Атанор* — піч алхіміка, в якій іде Велике Діло. Тут — виконавець мови Nigredo на Rust (лише `std`, без залежностей).

**Еталон — `interpreter/nigredo.py`.** Атанор не має своєї семантики: він повторює еталон дослівно — той самий вивід,
ті самі помилки й коди виходу, той самий підписаний слід (інше лише поле «інтерпретатор»: `атанор:<sha256 джерел>`).
Будь-яку розбіжність вважаю вадою Атанора.

## Збірка й запуск

```
sh athanor/зібрати.sh                      # друкує шлях до бінарника: athanor/target/<ціль>/release/athanor
athanor/target/<ціль>/release/athanor програма.ngr    # аргументи — як у ngr
```

Збірка — під glibc (`aarch64-unknown-linux-gnu` і т. ін.): XML і SQLite беруться з тих самих системних `libexpat` і
`libsqlite3`, що й у Python (через `dlopen`), тож і повідомлення про помилки ті самі.

## Що Атанор віддає еталону

До будь-якої дії (запису в слід, виводу) Атанор вирішує, чи виконає програму сам. Якщо ні — `exec` еталона з тими
самими аргументами (`ATHANOR_WHY=1` — надрукувати причину). Еталону йдуть:

- будь-яка помилка до запуску (розбір, типи, печатка поза дозволами, невидимі символи, двійники…) — тексти помилок
  друкує еталон;
- інструменти `мережа.взяти`, `мережа.послати`, `процес`, `агент` і гліф `‖`;
- режими `--перевірити`, `--печатка`, `--розбір`, `--сухо`, `--повторити`, `--тести`, `--перевірити-слід`, `--памʼятка`.

## Як перевіряю

- `python3 athanor/звірка.py [-j N]` — кожну програму `.ngr` репозиторію запускає обидва виконавці з тим самим
  тимчасовим власником і порівнює код виходу, вивід, stderr і слід (без часу й хешів). Звіт — `athanor/ЗВІРКА.md`.
  2026-10-19: 4916 програм, 1962 виконано нативно — розбіжностей 0 (12 залежать від годинника й не порівнюються;
  програми з тисячами відмов — довше за 60 с у еталона, звіряти з `--час 400`).
- `python3 athanor/проба.py` — випадкові програми для чисел, регулярок, CSV, дат, схем, XML, SQLite (тисячі пар,
  розбіжностей 0).
- `ATHANOR_NO_FALLBACK=1` — не віддавати еталону (код 120), щоб звірка бачила, що виконано нативно.

## Швидкість (телефон, Termux/proot, Python 3.13)

| | Атанор | еталон на Python | Python |
|---|---|---|---|
| Запуск: програма з одним `»`, процесорний час (зі слідом) / `print(1)` | ~6 мс | ~95 мс | ~26 мс |
| 12 задач агента, медіана часу до Python | **0,49×** | 2,17× | 1× |
| 200 тис. слів / цикл на 200 тис. кроків / JSON на 25 тис. записів | 0,73× / 0,57× / 0,86× | 8,6× / 38× / 12× | 1× |

Звідки швидкість: розбір і перевірка — один прохід; імена розвʼязано до запуску (кроки вгору, номер); цикли над
`…` без створення списку; одне середовище на весь цикл для λ без замикань; свій алокатор без атомарних операцій;
апаратний SHA-256 для сліду (усі блоки одним викликом); FxHash; дерева цілих (`‰ × i i 7`) — одним проходом без
проміжних значень; `∫ ∀ №` — без списку результатів; `λx x` — без виклику; спільні значення для коротких рядків,
що повторюються (слова з `✂`, ключі й значення JSON); JSON-розбір без копій рядків; екранування й «невидиме» — по
8 байтів за крок; запис сховища — одним буфером. Межі (`--кроки`, `--розмір`, глибина) — ті самі, що в еталона, і рахуються так само.
