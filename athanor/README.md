# Атанор — нативний виконавець Nigredo

*Атанор* — піч алхіміка, в якій іде Велике Діло. Тут — виконавець мови Nigredo на Rust (лише `std`, без залежностей).

**Еталон — `interpreter/nigredo.py`.** Атанор не має своєї семантики: він повторює еталон дослівно — той самий вивід,
ті самі помилки й коди виходу, той самий підписаний слід (інше лише поле «інтерпретатор»: `атанор:<sha256 джерел>` —
sha256 від «шлях\0вміст\0» кожного файлу `src/` за абеткою і `Cargo.toml`; це відбиток джерел, не підпис і не хеш
бінарника). Будь-яку розбіжність вважаю вадою Атанора — і знаходили їх (суд 9: кінцева сигма, `\N{…}` і великі
повторення в шаблоні з даних, межа сліду, кроки SQLite, стек; суд 9б: SIGABRT на глибоких `☂`/`¿`/`∧`; суд 12: `⇅` з
ключами `●`/`○` — еталон брав `●` за 1, Атанор відмовляв, а звірка корпусу такого не мала; усе виправлено з тестами
обома виконавцями, а `⇅` тепер має свій порядок ключів у нормі). Помилки до запуску (імена, двійники, письма, типи)
Атанор лише помічає й віддає еталону: їхній текст і правило має одна реалізація, і звірка тут порівнює лише те, що
віддано (суд 12, Мовознавець).

## Збірка й запуск

```
sh athanor/зібрати.sh                      # друкує шлях до бінарника: athanor/target/<ціль>/release/athanor
athanor/target/<ціль>/release/athanor програма.ngr    # аргументи — як у ngr
```

Збірка — під glibc (`aarch64-unknown-linux-gnu` і т. ін.): XML і SQLite беруться з тих самих системних `libexpat` і
`libsqlite3`, що й у Python (через `dlopen`), тож і повідомлення про помилки ті самі.

## Що Атанор віддає еталону

До будь-якої дії (запису в слід, виводу) Атанор вирішує, чи виконає програму сам. Якщо ні — `exec` еталона з тими
самими аргументами (`ATHANOR_WHY=1` — надрукувати причину). Еталону йдуть:

- будь-яка помилка до запуску (розбір, типи, печатка поза дозволами, невидимі символи, двійники…) — тексти помилок
  друкує еталон;
- інструменти `мережа.взяти`, `мережа.послати`, `процес`, `агент`, `python` (міст до Python, 0.10-dev) і гліф `‖`;
- програми з підписом автора (0.10-dev): рядок, що починається з `※ підпис ed25519:`, коментар, схожий на нього, чи
  такий останній рядок файлу й у літералі (та сама посимвольна міра `sig_char`, що в еталона: де скелет Атанора дав би
  інше — таблиця винятків `SIG_CHARS`, звірена з еталоном на кожному символі Unicode; огляд 11б: досі `ｅｄ２５５１９`
  Атанор виконував сам), — перевірку Ed25519 і права «для_авторів» веде еталон. Програми **без** підпису Атанор виконує сам і при непорожньому
  «для_авторів» власника — якщо той простої форми (ключ рівно `ed25519:` і 64 hex малими, значення `{"імʼя",
  "дозволи"}`, не ключ малого порядку); інакше — еталону, бо крива форма — відмова еталона всім програмам (суд 11: досі
  будь-яке «для_авторів» вимикало Атанор для всіх програм машини);
- модулі з мережі (0.9): `⊃`, рядок якого містить `#` чи `://` або **починається** з `github.com/` чи
  `raw.githubusercontent.com/` (і локальний файл з таким шляхом) — сховище, чистоту, слід і повтор таких програм веде
  лише еталон. Локальний модуль, у шляху якого таке лише всередині (`./github.com/…`, `теки/github.com/…`), Атанор
  виконує сам — це звичайний локальний модуль; попередження «ЛОКАЛЬНИЙ файл, хоча шлях схожий на адресу» дають
  печатка, `--отримати` і `--перевірити-слід`, а їх і так веде еталон (огляд 10б, Новачок); і будь-яка програма, коли
  «джерела_модулів» власника незвичної форми
  (не `[]`, не `["github.com"]`, не просте дзеркало `http(s)://хост[:порт]/шлях/`);
- режими `--перевірити`, `--печатка`, `--розбір`, `--повторити`, `--тести`, `--перевірити-слід`, `--памʼятка`,
  `--схвалити`, `--формат`, `--repl`, `--отримати`, `--дозволи` (сам `--тести` запускає кожен тест тим самим Атанором, а `--сухо` Атанор
  виконує сам — ключі власника міряють той виконавець, яким іде `ngr`).

Віддача буває лише до першої дії: під час виконання Атанор нічого не передає (паніка — код 4, а не повтор еталоном),
тож подвійної дії не буває.

## Як перевіряю

- `python3 athanor/звірка.py [-j N]` — кожну програму `.ngr` репозиторію запускає обидва виконавці з тим самим
  тимчасовим власником і порівнює код виходу, вивід, stderr і слід (без часу й хешів). Корпус — усі `.ngr`, які
  відстежує git (крім архіву): той самий коміт — той самий прогін. Звіт — `athanor/ЗВІРКА.md`, у репозиторії, з
  комітом, sha256 бінарника й відбитком джерел у заголовку; числа нижче — з нього. При оголошенні 1.0 (`0300b27`;
  кожна програма — під замком ОС обома виконавцями): 24398 програм (разом з атаками судів 11, 12 і їхніх оглядів,
  двійниками рядка підпису, тестами модулів з мережі й набором сумісності), нативно 7599 — однаково 7579, розбіжностей
  0, 1403 програми з `⊃` з мережі чи схожим на адресу віддано еталону (так задумано: сховище й чистоту веде лише він), 20
  залежать від годинника (не порівнюються: програма з `🜔час`, а виконавці бігли в різні секунди — тож і число від прогону до прогону інше); решту
  Атанор віддає еталону ще до дії — там збіг за побудовою, а причини віддачі звіт перелічує (найбільше — печатка поза
  дозволами власника, мережа й процес, імена-числа й літери, яких UTS #39 не радить для імен: помилку пише еталон).
  На кандидаті 1.0-rc (`71616da`) — 19923 / 6285 / 0, при оголошенні 0.10 — 19293 / 6003 / 0, після огляду 11б (0.10-dev, `755e7db`) — 18349 / 5815 / 0, після суду 11 (`3baf70f`, чистий checkout) — 17594 / 5643 / 0, при оголошенні 0.9 — 17594 / 5677 / 0, після огляду 10б — 16771 / 5458 / 0, після суду 10 — 16771 / 5458 / 0, до суду 10 (0.9-dev) — 15128 / 5066 / 0, з побажаннями огляду 0.8.1е — 15104 / 5062 / 0, при оголошенні 0.8.1 — теж 15104 / 5062 / 0, після огляду 0.8.1д — 13792 / 4746 / 0, після огляду 0.8.1г — 12542 / 4430 / 0, після огляду 0.8.1в — 11332 / 4114 / 0,
  після огляду 0.8.1б — 10160 / 3800 / 0, після огляду 0.8.1 — 9030 / 3488 / 0, після суду 9д —
  7948 / 3178 / 0, після суду 9г — 6948 / 2869 / 0, після суду 9в — 6008 / 2560 / 0, після суду 9б — 5155 / 2313 / 0. Раніше корпусом було все з диска, разом із неопублікованими робочими
  файлами суддів, тож число гуляло: до суду 9 — 4916 програм (нативно 1962, розбіжностей 5 — межа сліду), після суду 9 —
  3807 (нативно 1778, 0). Звірка лише на програмах репо не бачить класів, де поведінку вирішують дані, — для цього
  наступна проба.
  Якщо еталон не встиг за `--час`, а Атанор встиг, еталон запускається ще раз із часом ×8.
- `python3 athanor/звірка_даних.py [програм] [виразів]` — програми з випадковими даними (шаблони регулярок і заміни з
  даних, регістр різними письмами, числа й порядки, JSON, дати, CSV, невидимі) обома виконавцями. Заморожена 0.8
  (до суду 9): 25 розбіжностей на 91 програмі; після виправлень: 0 на 249 програмах × 20 виразів.
- `python3 athanor/проба.py` — випадкові програми для чисел, регулярок, CSV, дат, схем, XML, SQLite (тисячі пар,
  розбіжностей 0).
- `ATHANOR_NO_FALLBACK=1` — не віддавати еталону (код 120), щоб звірка бачила, що виконано нативно.

## Швидкість (телефон, Termux/proot, Python 3.13)

| | Атанор | еталон на Python | Python |
|---|---|---|---|
| Запуск: програма з одним `»`, процесорний час (зі слідом) / `print(1)` | ~6 мс | ~95 мс | ~26 мс |
| 12 задач агента, медіана часу до Python | **0,44×** | 2,17× (вимір 2026-10-19) | 1× |
| 200 тис. слів / цикл на 200 тис. кроків / JSON на 25 тис. записів | 0,67× / 0,42× / 0,91× | 7,8× / 31× / 12× | 1× |
| той самий цикл через іменовану функцію / з `¿` у ній | 0,35× / 0,47× | 23× / 33× | 1× |
| точні дроби (у Python — `Decimal`) / складання рядків / `↻` зі станом-списком | 0,65× / 0,89× / 0,67× | 30× / 36× / 84× | 1× |

Звідки швидкість: розбір і перевірка — один прохід; імена розвʼязано до запуску (кроки вгору, номер); цикли над
`…` без створення списку; одне середовище на весь цикл для λ без замикань; свій алокатор без атомарних операцій;
апаратний SHA-256 для сліду (усі блоки одним викликом); FxHash; дерева цілих (`‰ × i i 7`) — одним проходом без
проміжних значень; `∫ ∀ №` — без списку результатів; `λx x` — без виклику; спільні значення для коротких рядків,
що повторюються (слова з `✂`, ключі й значення JSON); JSON-розбір без копій рядків; екранування й «невидиме» — по
8 байтів за крок; запис сховища — одним буфером. Межі (`--кроки`, `--розмір`, `--слід-розмір`, глибина) — ті самі, що в
еталона, і рахуються так само (кроки SQLite — за інструкціями; глибина — правило мови: виклики × висота тіла λ
≤ 200 000, парсери обох міряють висоту однаково, а фізичного стека — із запасом на межу). Годинник профайлера Атанор
питає лише під `ATHANOR_PROFILE` (під proot це системний виклик: функція з `¿` у циклі була втричі повільнішою).

Застереження до таблиці: малі задачі — здебільшого запуск інтерпретатора; дві задачі з мережею Атанор віддає еталону,
і там він повільніший за Python. «Великі дані» — до 0,1 с роботи Python; слова, цикл, JSON і функція — форми зі
швидкими доріжками (цикли над `…`, дерева цілих), `¿` у тілі — без окремої доріжки; `↻`, що щокроку будує новий
список, до 2026-10-27 був у 1,7 раза повільніший за Python, а точні дроби й рядки — нарівні з ним; тепер (листок
`§ імʼя ціле` у дереві цілих, загальні доріжки без зайвих копій) усі вісім — швидші (числа й розкид — у `bench/великі/`).
