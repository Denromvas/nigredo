# Nigredo — специфікація

Версія: **0.2** (2026-10-09). Попередня, 0.1 — в `архів/0.1/`; її засудив консиліум
(`konsylium/суд1_0.1/protokol/ПІДСУМОК.md`), і 0.2 перероблено з нуля з урахуванням вироку.

Довідник гліфів та інструментів із сигнатурами — `ДЛЯ_АГЕНТІВ.md`. Його генерує
інтерпретатор (`ngr --памʼятка`) з тих самих таблиць, якими виконує програми, тож
документація й мова не можуть розійтися (це перевіряють тести).

---

## 0. Прозорість (червона лінія №1)

Мова для агентів, але **власник завжди знає, що програма може зробити і що зробила**:

1. **Печатка** (§4) — перший рядок кожної програми: намір і *повний* перелік дозволів.
   Інтерпретатор ще до запуску відкидає програму, якщо вона торкається чогось поза печаткою
   або печатка виходить за дозволи власника. `ngr --печатка` показує її людині.
2. **Розбір** — `ngr --розбір` перекладає програму українським псевдокодом (зміст, а не назви гліфів).
3. **Слід** (§7) веде інтерпретатор, а не програма: JSONL, кожен запис зчеплено хешем із
   попереднім (`ngr --перевірити-слід`). Програма не має жодного способу писати в слід чи в stderr.

Межа чесності: печатка захищає від помилок і робить намір видимим. Агент, що має shell,
може обійти Nigredo взагалі; від зловмисника з shell мова не захищає й не вдає, що захищає.

## 2. Лексика

- **Гліф** — один символ із таблиці (`ДЛЯ_АГЕНТІВ.md`). Пробіли між гліфом і аргументом не потрібні.
- **Імʼя** — послідовність літер (будь-яке письмо, крім грецького), цифр, `_`, `ʼ`; починається з літери.
  Грецькі літери — завжди гліфи (`λ μ φ ρ σ ν δ Δ Σ Λ κ`), тож `λx` — це `λ` і `x`.
  Імена з крапкою (`файл.читати`) бувають лише після `🜔`.
- **Число** — цифри будь-якого письма Unicode (`42`, `４２`, `٤٢`), необовʼязково `.`/`·` і дробова
  частина; `¯` перед числом — мінус (`¯5`). Числа й імена, що стоять поруч, розділяє пробіл.
- **Рядок** `「…」`; екранування `\」 \n \t \\`.
- Дужки: `【…】` список, `『ключ значення …』` словник, `《…》` блок.
- `※` — коментар до кінця рядка. `¦` — кінець виразу (як новий рядок).
- Будь-який інший символ — помилка. Для звичних ASCII-операторів інтерпретатор підкаже гліф
  (`+` → «може, ＋?»).

## 3. Значення й впевненість

Типи: число (ціле/дійсне), рядок, `●`/`○` (істинність), `∅` (ніщо), список, словник
(ключі — рядки), функція.

- Умови (`¿ ∧ ∨ ¬ φ ↻ 🜍`) приймають **лише** `●`/`○`; інше — помилка.
- `＝` порівнює глибоко; `1 ＝ 1.0` — `●`; `●` не дорівнює `1`.
- Значення **незмінні**. `←` називає назавжди; повторне `←` того самого імені в тій самій
  області — помилка розбору. Блок `《》` і функція відкривають нову область.

**Впевненість.** Кожне значення несе `c ∈ [0, 1]`, типово 1.
- Результат гліфа має впевненість найменш упевненого аргументу (мінімум, а не добуток:
  `＝ x x` має ту саму впевненість, що й `x`).
- `¿`: результат має `min(впевненість умови, впевненість обраної гілки)` — розгалуження не
  «відмиває» сумнів.
- Елементи списку й словника зберігають власну впевненість; `§` повертає елемент як є.
- `≈ x c` — єдиний спосіб змінити впевненість (вгору чи вниз); кожен виклик записується в слід.
- `± x` — впевненість (сама вона має впевненість 1). `⚗ список поріг` лишає елементи з `c ≥ поріг`
  і записує в слід кожне рішення «лишено / відкинуто».
- Результат інструмента має впевненість, яку дав інструмент, обмежену впевненістю аргументів.

## 4. Синтаксис і виконання

Програма — послідовність виразів. Вираз — літерал, імʼя, дужки або гліф, за яким іде рівно
стільки виразів, скільки його арність. Отже дерево однозначне і відоме до запуску.

- Вираз, не завершений у кінці рядка, продовжується на наступному. Якщо ж вираз завершився,
  а в рядку ще щось є — помилка розбору («зайве чи бракує аргументу раніше?»).
- `← імʼя вираз` називає значення. Якщо вираз — `λ`/`Λ`, імʼя видно в тілі (рекурсія), і
  такі функції викликають напряму: `факт 10`. Функцію-значення (параметр, елемент списку)
  викликають `► f x` / `▶ f a b`.
- `¿` обчислює лише одну гілку. `☂ вираз λe обробник` перехоплює помилки програми, але не
  межі виконання (кроки, глибина).
- Ліміт кроків (`--кроки`, типово 10 млн) і глибини рекурсії (2000).

**Печатка.** Перший вираз програми — `🜂 「намір」 【「дозвіл」 …】`, лише один раз:
- Дозвіл — `「інструмент」` або `「інструмент:обмеження」`. Для `файл.*` обмеження — тека
  (відносно теки програми; дозволено все в ній), для `мережа.взяти` — хост, для `агент` — імʼя.
- `🜔інструмент`, якого нема в печатці найближчого агента, — помилка розбору.
- Перед запуском печатка звіряється з **дозволами власника** — `~/.nigredo/дозволи.json`
  (`{"дозволено": ["оракул", "файл.читати:/абсолютна/тека", …]}`) або файлом `--дозволи`.
  Без файлу дозволено лише `оракул`, `жереб`, `час`. Чого бракує — програма не запускається
  (код 3), а відмова потрапляє в слід.
- Під час виконання кожен шлях перевіряється після `realpath`: вийти через `..` чи
  символічне посилання не можна.

**Делегування.** `🜁 「імʼя」 「намір」 【дозволи】 вираз`:
- дозволи субагента — підмножина дозволів батька (перевіряється до запуску; `「файл.читати」`
  без обмеження успадковує обмеження батька, з обмеженням — має бути одним із батьківських);
- субагент бачить імена батька (вони незмінні, тож змінити їх неможливо) і має власну
  порожню памʼять; імена, які він називає, батькові не видно;
- помилка субагента стає помилкою батька з префіксом `у субагенті «імʼя»:`;
- «Субагент» виконується в тому самому процесі. Справжній інший агент — інструмент `агент`.

## 5. Інструменти

Таблиця з сигнатурами — `ДЛЯ_АГЕНТІВ.md`. Коротко:

| Інструмент | Що | Обмеження |
|---|---|---|
| `оракул` | **імітація** ненадійного джерела (відповідь і впевненість 0.3–0.99 з SHA-256 питання) | — |
| `жереб`, `час` | випадкове ціле (детерміноване `--зерно`), поточний час UTC | — |
| `файл.читати`, `файл.писати`, `файл.список` | текстові файли, до 2 МБ | тека |
| `мережа.взяти` | HTTP(S) GET, до 1 МБ, 30 с | хост |
| `агент` | `claude -p` у теці агента з реєстру лаунчера. **Увага:** викликаний агент діє з *власними* правами (його `.claude/settings*.json`), тобто може робити все, що там йому дозволено. Дозвольте лише тих агентів, чиїм правам довіряєте | імʼя |

Процесів і shell немає навмисно.

## 6. Помилки й коди виходу

`✗ рядок:стовпець повідомлення`. Код 0 — гаразд, 1 — помилка під час виконання,
2 — помилка до запуску (розбір, імена, печатка), 3 — печатка за межами дозволів власника.

## 7. Слід

`--слід файл.jsonl` (або `-` — stderr). Кожен запис — JSON-обʼєкт: `№`, `подія`, `глибина`
(делегування), `агент` (шлях `головний/провидець`), дані події, `попередній` і `хеш`
(перші 16 hex SHA-256 запису без хешу). Події: `початок` (sha256 програми, дозволи власника),
`печатка`, `відмова`, `інструмент` (аргументи, результат, впевненість або помилка),
`делегування`, `субагент повернув`, `субагент впав`, `памʼять`, `перевірка`, `впевненість`,
`відсів`, `помилку перехоплено`, `вивід`, `помилка`, `кінець`. Усі рядки екрановано JSON,
тож перенос рядка в намірі не створить фальшивого запису.

## 8. Командний рядок

```
ngr ФАЙЛ.ngr | -e КОД   [--слід ФАЙЛ|-] [--дозволи ФАЙЛ] [--зерно N] [--кроки N]
ngr --печатка ФАЙЛ       що дозволено (без виконання)
ngr --розбір ФАЙЛ        переклад (без виконання)
ngr --перевірити-слід ФАЙЛ
ngr --памʼятка           згенерувати ДЛЯ_АГЕНТІВ.md
```

## 9. Що змінилося після суду над 0.1

| Вада 0.1 (SPEC 0.1 §12) | У 0.2 |
|---|---|
| Межа делегування проникна | Значень, які можна змінити, немає взагалі; імена субагента не просочуються (тести 12, 03, 16). |
| Слід можна підробити | Слід пише лише інтерпретатор; JSON-екранування; ланцюжок хешів (тест 13). |
| Відсів через `⚖ ⋐` не в сліді; `⚗` суперечив сліду | `⚗` — окремий відсів за впевненістю; кожне рішення в сліді; `φ` вимагає ●/○. |
| Впевненість відмивалася `⋔`, `x≡x` → 0.25 | Мінімум замість добутку; `¿` успадковує впевненість умови. |
| Тихі збої (зміщена дужка, сміття на стеку) | Стека немає; зайве/бракує — помилка розбору (тести 05, 06). |
| Пастки пробілів, APL-«фальшиві друзі» | Гліфи з правильним математичним змістом; імена — слова; підказки для ASCII (тест 07). |
| Памʼятка без сигнатур | Памʼятка генерується з таблиць, із сигнатурами й прикладами, що проходять тести. |
| `--розбір` — глосарій | Переклад змісту: «для кожного n з ряд 1…15: надрукувати якщо …». |
| 2–2,5× Python у токенах | Без печатки ≈ Python за однакових імен (§10). |
| Нуль реальних можливостей | Файли, мережа, агенти, словники, JSON — з дозволу власника. |
| Немає ліміту кроків | `--кроки`; `☂` його не перехоплює (тест 11). |

## 10. Токени (виміряно 2026-10-09, tiktoken)

Ціна гліфа в контексті: старі гліфи 0.1 — близько 3 токенів; гліфи 0.2 — переважно 1–2
(CJK-дужки, `× ÷ ¬ λ μ φ ρ σ « » ¿ ※ ←`), алхімічні гліфи агента — 3 (вживаються рідко).

Три завдання консиліуму (FizzBuzz, рядок, агентне), код без коментарів, **однакові імена**:

| | cl100k | o200k |
|---|---|---|
| Nigredo 0.1 | 390 | 382 |
| Nigredo 0.2 з печаткою | 311 | 252 |
| Nigredo 0.2 без печатки | 237 | 202 |
| Python (агентні функції вигадані — у Python їх немає) | 237 | 199 |

Висновок: мова сама по собі вже на рівні Python; печатка — фіксована ціна за гарантії.
Кириличні імена дорожчі за латинські в 3–8 разів — це властивість токенізаторів, не мови.

## 11. Відкриті питання

1. Постійна памʼять між запусками (`🜄` у файл із дозволу власника).
2. Типи/сигнатури функцій користувача й перевірка до запуску.
3. Модулі (імпорт інших `.ngr` з їхніми печатками).
4. Підпис печатки власником (щоб агент не міг сам розширити `дозволи.json`).
5. Модель впевненості для залежних джерел (зараз — консервативний мінімум).
