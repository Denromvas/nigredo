Вивід Г (однаковий в обох, `звіти/звіт.txt` записано):
```
кава: 519.00

хліб: 114.00

```

**Де памʼятки Nigredo забракло і я вгадував** (усі здогади виявилися правильними, але це були здогади):
1. Чи відносні шляхи **в печатці** (`「файл.читати:дані」`) теж рахуються від теки програми. Памʼятка каже це
   лише про шляхи взагалі. Підтвердив через `ngr --печатка` (показує абсолютний шлях).
2. Чи можна викликати власну функцію, названу `←` (`сума`), посеред префіксного виразу (`⌗ сума §гр к 2`) і
   чи сам розбирач визначить її арність. У памʼятці є лише `факт 10` окремо.
3. Чи `φ` прийме JSON `true` з файлу як `●`. Памʼятка каже, що `true ↔ ●`, але не каже, що це те саме значення для умов.
4. Чи `»` додає перенос рядка і чи `\n` у `「」` дає справжній перенос у файлі. Перевірив через `cat -A`.
5. Яку впевненість має `ρ` (довжина) від списку з впевненістю. Памʼятка каже лише загально: «усе, що обчислено з даних».
6. Чи `✂` з одним пробілом відрізняється від `✂` з `「」`.

**Де забракло памʼятки ngrpy:**
1. `ngrpy.py -h` не існує: команда падає з трасою Python `FileNotFoundError: .../-h`.
2. Немає аналога `--печатка`/`--розбір`, і памʼятка не каже, як отримувачу подивитися печатку до запуску.
3. Не сказано, від чого рахуються відносні шляхи в `tool("файл.читати", …)`. Здогадався, що від теки скрипта.
4. Немає попередження, що `sorted()` у Python не знає української абетки (а в Nigredo `↑` і `⇅` це вміють).

Чесне застереження: два з чотирьох завдань (А, В) майже дослівно збігаються з прикладами памʼятки Nigredo, а Г
близький до прикладу «групування, гроші, абетка». Тому 4/4 з першої спроби показує, що **памʼятка добре підібрана
під ці завдання**, але не доводить, що мову можна вивчити для довільної задачі.

## Д. Атаки (що вдалося — у якій мові, з доказом)

Д5, спостереження (без атаки):
- **Абетка:** `sorted(["яма","іній","їжак","гора","ґанок","єнот","дім","ера"])` у ngrpy дає
  `['гора','дім','ера','яма','єнот','іній','їжак','ґанок']`, тобто неправильно. `↑` у Nigredo дає правильний порядок
  `гора ґанок дім ера єнот іній їжак яма`. В обох мовах звіт Г з такими категоріями був би хибним без жодної помилки.
- **Дозволи власника спільні для всіх учасників.** Запис `початок` у сліді показує, що власник дозволив читати
  `дані/` і писати в `звіти/` **кожного** учасника (skeptyk, praktyk, audytor, …). Отже, моя печатка могла б законно
  попросити `файл.писати:…/skeptyk/звіти`, і обидва інтерпретатори, судячи з усього, це пропустили б. Я **не
  перевіряв** запуском, бо правила забороняють торкатися чужих тек. Це питання до налаштування дозволів, а не до мови.
- **Слід ngrpy бідніший для субагентів:** виклики інструментів субагента мають `"глибина": 0` (у Nigredo — `1`),
  а `субагент повернув` не містить результату й впевненості (у Nigredo — містить).

## Голос

Мій голос: **А** — для вузького класу задач, де потрібні печатка й слід.

Обґрунтування: у моїх запусках ngrpy **не дала тих самих гарантій**. Дві з чотирьох цілей атаки (вивід повз слід,
підйом впевненості без запису) у ній вдалися простими публічними засобами з памʼятки, а в Nigredo — ні. Чужа
програма е3 показала, що печатка ngrpy нічого не гарантує отримувачу до запуску. Новачок написав усі чотири
завдання Nigredo з першої спроби лише з памʼятки. Тож вимога «ngrpy з тими самими гарантіями» не виконана, а
отже, ngrpy не замінює Nigredo там, де гарантії і є метою.

Умови:
1. Для бібліотечних і практичних задач — звичайний Python (або ngrpy). Nigredo — лише там, де отримувачу треба
   довіряти чужій програмі без читання її коду.
2. Перевірити новачками на задачах, **яких немає серед прикладів памʼятки** (мій результат 4/4 цього не доводить).
3. Дописати в памʼятку пункти 1–6 з розділу «де забракло».
4. Окремо від мови: дозволи власника для суду спільні для всіх учасників. Їх варто розділити.
