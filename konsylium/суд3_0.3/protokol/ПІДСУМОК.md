## Головні факти

- **ngrpy не дає тих самих гарантій — показано запуском:** аудит-хук вимикається зсередини (`ngrpy._ST`,
  `tool.__closure__`, навіть через публічний `check()`); впевненість відмивається `U(value(x), 1.0)` без сліду;
  `sys.stdout.write` повз слід; підписаний ключем власника вигаданий слід. Усі визнали: обгортку зроблено
  чесно, це межа мови-господаря (в одному процесі інтроспекція сильніша за будь-який хук).
- **Межа Nigredo «печатка → інструменти → файли» встояла в усіх семи** (запис, читання поза текою, теку
  власника, обхід через субагента — відбито, здебільшого ще до запуску).
- **Е (чужі програми):** для `.ngr` рішення «запускати чи ні» — один рядок печатки (секунди); для `.py` —
  читати весь код, і `е3.py` з чесною на вигляд печаткою все одно тягнулася до дозволів власника.
- Мовознавець/Скептик: гарантії дають не гліфи, а відсутність «довкілля» (ambient authority) у семантиці —
  те саме дала б мова без власних повноважень із Python-синтаксисом (Starlark-подібна). Гліфи — не джерело безпеки.

## Діри Nigredo 0.3 (відтворено)

1. **Впевненість через контекст керування:** вибір елемента за сумнівним значенням (`§ φ …`, `⚗ φ …`, `⇅`, `⊞`,
   `🜃` з ключем від даних, `►` функції, обраної `¿`) дає «певний» результат — потрібна мітка pc.
2. **Перевірка сліду** вважає проміжну `відмова` завершальною — обрізаний після неї слід «цілий».
3. **Немає ліміту памʼяті/розміру значень** (рядок до 16 млн символів за 182 кроки).
4. Дозволи власника — один список на всіх (вада налаштування суду; потрібні дозволи на програму/агента).
5. `--розбір` без дужок навколо складених підвиразів; памʼятка обіцяє більше, ніж виконує.
