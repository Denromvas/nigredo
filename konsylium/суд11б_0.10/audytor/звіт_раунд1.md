## 4. Н — нове

### Н-1. Модуль з теки запису «для_авторів» береться

Правило мови: код, який могла написати програма, — не модуль. Для тек ключа воно не діє.

**Відтворення** (обома; Атанор — нативно):
1. `н1_пише_модуль.ngr` має печатку лише `писати:підписане`. Без підпису: «печатка просить більше». Підписана моїм
   ключем, вона пише `підписане/мод_написаний.ngr` — модуль з функцією, що читає `дані/`.
2. `н1_імпорт.ngr` — звичайна непідписана програма теки з `читати:…/audytor/дані`. Вона робить `⊃` цього модуля і
   друкує 179 обома.
3. `--печатка --json`: `в_межах: true`, `попередження: []`.
4. Контроль: той самий файл у `звіти/` дає «модуль … лежить у теці, куди програмам дозволено писати» обома.
5. Те саме з `від-агента/мод_агента.ngr` — 179. `від-агента/` — тека запису ключа «агента звітів» у всіх семи теках
   суддів.

**Причина** (`nigredo.py`):
- `write_dirs()` (`:8433`) бере теки запису з «дозволено», «для_тек» і «для_програм», але **не з «для_авторів»**.
- `read_allowlist` (`:5525–5528`) «для_авторів» бере, тому виправлення 19 і спрацювало лише для розташування програми.
- `write_dirs()` використовують ще три перевірки:
  - модулі й виконувані файли `процес` у `check_program` (`:6007`);
  - `t_proc` (`:4725`);
  - вибір тестів `--тести` (`:8469`).

  `--тести --печатка .` бере `підписане/т_у_теці_ключа.тест.ngr`, а такий самий файл у `звіти/` пропускає. Прав теки
  такий тест, перевірено, не має.
- Атанор поводиться так само: розбіжності немає, вада спільна.

**Наслідок:**
- Право ключа «писати:X» стає правом «покласти код, що виконається з правами теки» для кожної програми, яка візьме
  модуль з X. Це рівно те, що правило забороняє для `звіти/` і `схвалене/`.
- «Агент звітів» може так покласти код у `від-агента/` семи тек.
- Слід чесний (`модуль`, sha256), але печатка не попереджає.

**Виправити:** додати до `write_dirs()` (і в Атанора) записи «дозволи» з «для_авторів», плюс тест обома: модуль, тест
і `процес` з теки ключа.

### Н-2 (дрібне). Двійник рядка підпису великими літерами

`※ підпис ED25519:<ключ агента звітів> …` (також `Ed25519`, `ed_25519`) обидва виконавці виконують як звичайну
програму. Скелет UTS #39 регістру не згортає.

Прав це не дає:
- `--перевірити-підпис` — «підпису немає», код 1;
- `--печатка` про підпис мовчить;
- `--розбір` коментарів не показує.

Але людина бачить у тексті підпис відомого ключа, а мова — ні. Саме цього виправлення 9 мало уникнути. Шукати
«ed25519» без урахування регістру й `_`.

Ціна цього правила — хибна відмова. Звичайний коментар `※ тут буде перевірка ed25519 вручну` дає код 3. SPEC (§5) про
це каже. Безпечний бік.

### Н-3 (дрібне). Два ⚠ печатки суперечать одне одному

Для `builtins.open`, `linecache.getlines`, `os.pidfd_open` печатка поруч пише:
- «читати поза теками Python міст не дає»;
- «така функція може прочитати будь-який файл користувача».

Запуск показує, що для `open` і `linecache` стеження тримає. Друге ⚠ надто обережне, бік безпечний. Краще не ставити
ці функції в перше ⚠.
