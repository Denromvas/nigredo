## 3. Н — нове на виправленнях

- **128-бітна випадкова назва UDF та приманка `ngr_rowid`:** Справжня функція створюється з новим випадковим ім'ям на кожен запит і доступна виключно тимчасовим тригерам самого інтерпретатора в `temp`. Старе ім'я `ngr_rowid` залишено як приманку: authorizer завжди відхиляє його, а попередня перевірка бачить у байткоді. Спроби підробити «запобіжну відмову» через схему відсутні.
- **Захист схеми `temp`:** Прямий доступ до схеми `temp` (`SELECT sql FROM temp.sqlite_master`) повертає відмову: «заборонено: службові тригери інтерпретатора (текст схеми temp) — програма їх не читає». Отримати 128 біт випадковості без дозволу «жереб» або дізнатися згенероване ім'я неможливо.
- **Штатна робота SQLite DDL (`ALTER TABLE`):** Перевірено виконання `ALTER TABLE … RENAME`, `ADD COLUMN` та наступні операції DML. Запити проходять штатно, зміна схеми не ламає роботу бази, хибних тривог немає.
- **Штатне виконання завдань (А, Б, В):**
  - **Завдання А** (читання JSON, HTTP GET 3 товарів, точна сума): вивід `285.60`, код виходу 0 (1 запуск).
  - **Завдання Б** (розбір XML camt.053, XPath `//Ntry`, фільтрація CRDT, групування, сортування): суми та порядок зійшлися повністю, код виходу 0 (1 запуск).
  - **Завдання В** (контракти даних `✓`, типи `τ`, логіка `∧`/`∨`): коректна валідація обох файлів, повний вивід розбіжностей для дефектного рахунку, код виходу 0 (1 запуск).
- **Неперевірене:** безпосередньо у сесії не викликалися сеанси REPL, команди `--формат` та схема `--схвалити` (оцінено статично за кодом і документацією).
