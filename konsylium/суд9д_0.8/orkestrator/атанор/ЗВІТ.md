# Атанор проти еталона: розбіжності й паніки (помічник Оркестратора, суд 9)

Усе нижче запущено: `ngr` (Атанор) і `python3 /root/ai-agents/Nigredo/interpreter/ngr.py` (еталон), файли
проб у цій теці. Слід Атанора — `атанор/с_*_а.jsonl`, еталона — `с_*_е.jsonl`. Жодна проба не віддалася еталону
(`ATHANOR_WHY=1` нічого не друкував), тобто все виконав сам Атанор.

## Підтверджені вади

### 1. (пріоритет 1) Переповнення стеку Атанора: аварійне завершення, слід обірвано — `а_06_стек_атанора.ngr`

Програма проходить усі перевірки до запуску (вкладеність 950 < MAX_NEST 1000, глибина викликів 1990 < MAX_DEPTH 2000).
Атанор не має межі на сумарну глибину стеку (лише окремо на виклики й вкладеність тексту), стек потоку — 512 МБ,
і рекурсивний `eval` переповнює його: процес вбиває рантайм Rust (SIGABRT), без «внутрішньої помилки», без запису
«помилка» в слід. Запис «вивід» до рекурсії вже є, тож слід виглядає як підрізаний.

Текст (скорочено; повний — у файлі): печатка `🜂 「…」 【】`, далі
```
← f λn ¿ ≤ n 0 0
  ＋ 1 ＋ 1 … (950 разів ＋ 1, рядки продовження з відступом)
  f － n 1
» 「перед рекурсією」
» ☂ f 1990 λe 〔перехоплено: {e}〕
```
Відтворення:
```
timeout 300 ngr атанор/а_06_стек_атанора.ngr --слід атанор/с_06_а.jsonl
ngr --перевірити-слід атанор/с_06_а.jsonl атанор/а_06_стек_атанора.ngr
python3 /root/ai-agents/Nigredo/interpreter/ngr.py атанор/а_06_стек_атанора.ngr --слід атанор/с_06_е.jsonl
```
Атанор: `перед рекурсією` / `thread '<unknown>' (13105) has overflowed its stack` / `fatal runtime error: stack overflow, aborting`;
перевірка сліду: `✗ слід обірвано: 3 записів, останній — «вивід», а не кінець/помилка/відмова на старті`.
Еталон: `перед рекурсією` / `✗ внутрішня помилка інтерпретатора Nigredo (RecursionError: maximum recursion depth exceeded)`,
код 4, останній запис сліду — `"подія": "помилка", "внутрішня": true`.
Поріг (а_07, глибина з аргументу): 400×950 — ще працює, 1000×950 — abort.

### 2. (пріоритет 2, рівень командного рядка) Атанор запускає програму з `--зерно`, яке еталон відхиляє — `а_04_зерно.ngr`

`int_arg` у `athanor/src/main.rs` перевіряє лише, що після зрізання всіх `-`/`+` на початку лишилися цифри, тож приймає
`+-5`, `-+5`, `--5`; для `--зерно` рядок не перетворюється на число (у `--кроки`/`--розмір` це робить `parse`, і там
воно падає й віддає еталону). Еталон робить `int(next(it))` → ValueError.
```
ngr атанор/а_04_зерно.ngr --зерно +-5 --слід атанор/с_04б_а.jsonl          → код 0, «гаразд», слід є
python3 …/ngr.py атанор/а_04_зерно.ngr --зерно +-5 --слід атанор/с_04б_е.jsonl → код 1, трасування Python
                                        «ValueError: invalid literal for int() with base 10: '+-5'», сліду немає
```

### 3. (пріоритет 4, але слід не проходить перевірку) `--зерно 007` (чи `-0`) — у сліді не JSON — `а_04_зерно.ngr`

`"зерно"` у записі «початок» пишеться як `J::Num` з сирого тексту аргументу (`main.rs`, «ліміти»): `007` → `"зерно": 007`
(недійсний JSON), `-0` → `-0`. Еталон пише `int` → `7` / `0`. Той самий запис іде й у головний слід у теці власника.
```
ngr атанор/а_04_зерно.ngr --зерно 007 --слід атанор/с_04_а.jsonl
ngr --перевірити-слід атанор/с_04_а.jsonl атанор/а_04_зерно.ngr   → «✗ слід пошкоджено в рядку 1: це не запис сліду»
(слід еталона з тим самим аргументом: «✓ слід цілий і завершений (кінець): 4 записів»)
```

### 4. (пріоритет 3) Порядок ≥ 10^18 у `ν` і `δ` — інше повідомлення — `а_02_порядок_1e18.ngr`

`Dec::parse` (athanor/src/dec.rs) обрізає довгий порядок до 2^55, а Python `Decimal('1e1000000000000000000')`
(порядок > MAX_EMAX = 10^18−1) кидає InvalidOperation. Під `☂` різниця видна в тексті програми.
```
🜂 「проба: ν і δ з порядком 10^18 (понад MAX_EMAX десяткових Python)」 【】
» ☂ ν 「1e1000000000000000000」 λe e
» ☂ ν 「1e999999999999999999」 λe e
» ☂ δ 「1e1000000000000000000」 λe e
» ☂ δ 「[1.5e99999999999999999999]」 λe e
» ☂ ν 「1e100000」 λe e
```
Атанор, рядки 1/3/4: `ν: порядок числа понад 30000 цифр`, `δ: порядок числа понад 30000 цифр` (×2).
Еталон: `ν: «1e1000000000000000000» не число`, `δ: десяткове число поза межами (InvalidOperation)` (×2).
Рядки 2 і 5 збігаються.

### 5. (пріоритет 3) Глибоке тіло рекурсії: еталон падає (код 4), Атанор виконує — `а_05_рекурсія_глибоке_тіло.ngr`

```
🜂 「проба: …」 【】
← f λn ¿ ≤ n 0 0 ＋ 1 ＋ 1 … (60 разів) f － n 1
» ☂ f 1900 λe 〔перехоплено: {e}〕
```
Атанор: `114000`, код 0. Еталон: `✗ внутрішня помилка інтерпретатора Nigredo (RecursionError: maximum recursion depth
exceeded)`, код 4. Межа еталона — стек Python (setrecursionlimit 100 000 кадрів), у Атанора її немає (а своя — 512 МБ,
див. ваду 1). Еталон із тілом 950 при N=100 ще рахує (`95000`, як і Атанор); більших N еталоном не запускав.

## Що збіглося (не вади)

- `×` на межі 100 000 біт (а_01): обидва мають той самий «швидкий шлях цілих» без перевірки суми бітів.
- 46 гліфів одним запуском (а_03): вивід, слід (без часу/хешів), сховище `.дані` і кількість кроків — байт у байт.
- Читанням коду звірено й не знайдено розбіжностей: JSON-сканер (повідомлення й позиції як у C-сканері Python),
  CSV-автомат (дослівно з `_csv.c`), дати ISO, схеми `✓`, регулярки (розбір як `re._parser`, `expand` з вадою `²`),
  `realpath`, `deep_eq` (спільний `Rc` = `is`), `capc` з нерекурсивним шляхом, облік розміру десяткових.
- Зауваження без проби: `path_ok` Атанора кешує `realpath` теки з печатки (`rp_cache`), еталон рахує щоразу; якщо
  символьне посилання теки змінить хтось ззовні під час запуску, рішення можуть різнитися.
