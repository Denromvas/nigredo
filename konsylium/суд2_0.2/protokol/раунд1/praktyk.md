## Вади 0.1 — чи виправлено?

1. **Межа делегування проникна — ЧАСТКОВО, ні.** Переписати імʼя батька вже не можна (значення незмінні). Але субагент, якому дано лише `【「оракул」】`, викликав `🜔час` через функцію батька `← котра λx 🜔час` — і отримав час; у сліді: `"агент": "головний/гість", "назва": "час"`. Перевірка дозволу в `🜁` — лише лексична (у тілі делегування), а замикання батька несуть його права. Для файлових інструментів та сама спроба (`читай`/`пиши` батька з субагента) не проходить — але не відмовою, а **падінням інтерпретатора** з Python-трасою `KeyError: 'файл.читати'` / `'файл.писати'` (`/root/.local/bin/ngr`, рядок 574). `агент` не перевіряв (коштує грошей), але логіка та сама, що й для `час`.
2. **Слід можна підробити — так, виправлено** в тій частині, що була: програма не пише в слід, рядки екрановано, ланцюжок хешів. **Нова діра:** `--перевірити-слід` приймає обірваний слід. Після падіння (п.1) слід мав 3 записи без `помилка`/`кінець`, і перевірка сказала `✓ слід цілий: 3 записів`. Тобто обрізаний хвіст сліду не виявляється.
3. **Слід неповний/суперечить — так.** `⚗` пише кожне рішення «лишено/відкинуто» з впевненістю (В: 5 записів `відсів`, усе збігається з виводом).
4. **Відмивання впевненості — частково.** `¿`, `＝`, `σ`, памʼять зберігають мінімум (оракул 0.46 → 0.46 скрізь). Але `← b ＝ 1 ρ φ 【a】 λx ＝ x ○` дає `●` (тобто «оракул сказав ○») з `± b` = **1**, без жодного `≈` у сліді. `φ` не переносить впевненість умови на результат.
5. **Тихі збої — здебільшого так.** Зайве/бракує аргументу — помилка до запуску (`✗ 3:6 бракує аргументу`); невідоме імʼя в невиконаній гілці теж ловиться до запуску; `φ` з `「так」` замість `●` — чесна помилка. Лишилися тихі: `§ словник 「нема」` → `∅` без помилки; `»` показує `0.3` для `＋ 0.1 0.2`, а `＝ ＋0.1 0.2 0.3` → `○` (`Δ` дає `0.30000000000000004`).
6. **Лексичні пастки — частково.** Підказки для ASCII чудові (`>` → «може, ›?», `"` → «може, 「…」?»). Але `＋ ＝ －` — повноширинні, а `› ‹ ≤ ≥` — ні; повноширинне `＞` (логічне продовження `＋＝`) дає «невідомий символ «＞»» без підказки. Я сам на цьому спіткнувся.
7. **Памʼятка без сигнатур — так, виправлено.** Сигнатури, приклади й розділ «Пастки» є; Г я написав лише з таблиці.
8. **`--розбір` як глосарій — так, виправлено.** Для Г: `оплачені ← ті o з замовлення, де o[«оплачено»]` — це справді переклад змісту, людина-бухгалтер прочитає.
9. **Ліміт кроків — так.** `↻ 0 λs ● λs s` з `--кроки 100000` → `✗ перевищено ліміт кроків`, `☂` не перехопив.

## Нові вади 0.2

1. **Падіння інтерпретатора з Python-трасою** (п.1 вище): ~70 рядків трасування замість `✗ рядок:стовпець`, слід без запису про помилку. Для чергового агента о 3-й ночі це найгірший вид помилки.
2. **SPEC ≠ інтерпретатор:** SPEC §4 — «`「файл.читати」` без обмеження успадковує обмеження батька»; насправді `✗ 3:28 «файл.читати» потребує обмеження`. Памʼятку генерують з коду, а SPEC — ні, і вони вже розійшлися.
3. **Гроші у float без засобів округлення.** Є лише `⌊`; немає округлення до копійок і форматування `245.50` (`σ 245.5` → `245.5`, а `Δ 519.0` → `519.0`, тоді як `σ` → `519`). Для кас і 1С це щоденна потреба.
4. **Бідна робота з текстом для реальних даних.** Немає заміни, пошуку підрядка, обрізання пробілів, регістру, дат. Десяткову кому `「245,50」` (`ν` → помилка) довелося міняти через `⁀ ✂ s 「,」 「.」`. BOM у CSV не знімається: заголовок `﻿Номер` ≠ `「Номер」` (тихо `○`). Кодування cp1251 перевірити не зміг (не мав дозволу створити такий файл) — не знаю.
5. **Продуктивність словників надлінійна:** 20 000 ключів через `✎` — 2.0 с, 40 000 — 6.7 с (×2 даних → ×3.4 часу). Для довідника номенклатури на 100k позицій це вже хвилини. Звичайна згортка 200 000 чисел — 2.2 с, прийнятно.
6. **Діагностика без контексту даних:** `✗ 4:3 φ: умова має бути ● або ○, а не рядок 「так」` — добре, але не каже, *який* елемент (№ запису). На 10 000 замовлень шукатимеш руками. Немає `mkdir` (`звіти/підтека/x.txt` → `No such file or directory`); системні помилки ОС англійською.

## Оцінки (1–10)

- Зрозумілість для ШІ-агента: **7** — 4 з 4 з першої спроби, Г — без шаблону; префіксна арність + повідомлення «до запуску» реально допомагають. Мінус за непослідовні повноширинні гліфи.
- Виразність: **6** — `μ φ Σ ✎ δ` покривають задачі на кшталт Г компактно; бракує групування, рядкових операцій, округлення.
- Практична користь для реальної роботи агентів: **3** — справжні файли й печатка — крок уперед від 0.1 (там було 2), але для 1С/кас бракує базового (гроші, CSV, дати, текст), а будь-який агент з Python зробить те саме швидше і з бібліотеками.
- Прозорість для людини-власника: **7** — `--печатка`, `--розбір`, слід добрі й зрозумілі. Мінус за проникне делегування та «цілий» обірваний слід: саме там прозорість мала б бути гарантією.

## Сильні сторони

1. **Печатка + дозволи власника працюють:** вихід через `..`, абсолютний шлях `/etc/passwd`, запис поза `звіти` — усе відбито чітким повідомленням; `--печатка` з `--дозволи` одразу каже «✓ у межах».
2. **Помилки до запуску і підказки:** програма з помилкою в 8-му рядку не надрукувала нічого з перших семи — ніяких половинчастих запусків через синтаксис. Підказки для ASCII (`=` → `＝`, `(` → `《…》`).
3. **`--розбір` і слід** — їх реально можна показати власнику; слід Г читається як журнал операцій.

## Слабкі сторони

1. Межа делегування знову проникна (через замикання), а для файлів — падіння інтерпретатора замість відмови.
2. Немає інструментарію для реальних даних: округлення грошей, рядкові операції, дати, кодування, `mkdir`, групування.
3. Перевірка сліду не виявляє обрізаний хвіст; SPEC розходиться з кодом.

## Пропозиції

1. Перевіряти дозволи **динамічно** — за поточним агентом у момент виклику `🜔`, а не лексично; відмову писати в слід як `відмова`. Тест: функція батька з інструментом, викликана з субагента.
2. Ловити всі внутрішні винятки інтерпретатора в `✗ …` + запис `помилка` у слід; `--перевірити-слід` має вимагати завершального `кінець` (або явно казати «слід обірвано»).
3. Додати мінімум для бухгалтерії: округлення до N знаків, форматування числа, заміна/пошук/обрізання в рядках, знімання BOM, розбір CSV і дат. Без цього Г у реальному житті не пишеться.
4. Позначати в помилках індекс/ключ елемента, на якому впало `μ φ Σ ∀`.
5. Узгодити гліфи порівняння (або всі повноширинні, або всі ні) і додати підказку для `＞ ＜`; генерувати SPEC-розділи з того самого коду, що й памʼятку.

## Голос

А — прийняти як спільну робочу мову агентів
Б — лишити як експериментальну мову (не для реальної роботи)

Мій голос: **Б** — 0.2 — це справжній стрибок від 0.1: я розвʼязав усі чотири завдання з першого запуску, печатка й дозволи на файли працюють, слід і `--розбір` уже можна показувати власнику. Але головна обіцянка мови — безпечне делегування — знову не тримається (субагент з `「оракул」` викликав `час` через замикання батька, файлові спроби валять інтерпретатор), обрізаний слід проходить перевірку, а для реальної роботи (гроші, CSV, текст, дати) бракує базових засобів. Умови: не використовувати `🜁` як межу безпеки й `--перевірити-слід` як доказ повноти, доки не виконано пропозиції 1–2; повернутися до питання «А» після пропозиції 3 і повторної перевірки на справжньому завданні з 1С/каси.
