## Вади 0.1 — чи виправлено? (так / ні / частково — з доказом)

1. **Межа делегування проникна — так (у межах моєї проби).** `проби/субагент.ngr`: субагент робить `← x 5` у своєму блоці → це затінення, не зміна; батько після делегування друкує `x` = `1`. Змінних, які можна змінити, у мові просто немає.
2. **Слід можна підробити — так (ланцюжок перевірив, атаку не відтворював).** `ngr --перевірити-слід слід_В.jsonl` → `✓ слід цілий: 27 записів`. У програми немає гліфа для запису в слід/stderr. Атаку з переносом рядка в намірі сам не пробував — лишаю Аудиторові.
3. **Слід неповний / суперечить результату — так для `⚗`.** Кожне рішення відсіву в сліді (записи 18–22) і збігається з результатом `【○ ●】`. Але див. п. 4: відмивання впевненості в слід не потрапляє.
4. **Впевненість відмивається — частково.** Для скалярів правило мінімуму працює (`± ¬ v`, `± δ Δ v`, `± ＋「x」 σv`, `± Σ【v】 0 Λa x ¿ x 1 0` — усі 0.46). Але **контейнер має впевненість 1 незалежно від вмісту**, і через нього сумнів зникає без `≈` і без запису в слід (v = оракул, 0.46):
   - `± ＝ 【v】 【●】` → **1**
   - `± ¿ ＝ ρ φ【v】 λx x 1 ● ○` → **1** (булеве значення, рівносильне v, але «певне»)
   - `± ＝ σ【v】 「【○】」` → **1**
   Тобто «впевненість не відмити» (SPEC §1) не виконується: досить загорнути значення в `【】`.
5. **Тихі збої — частково.** Зайве в рядку — справді помилка (`» 1 2` → «вираз уже завершено…»). Але **бракуючий аргумент мовчки забирає наступний рядок**:
   ```
   ← ціна ＋ 100
   ← податок 20
   » ціна          ※ друкує 120, без жодної помилки; «податок» теж визначено
   ```
   `--розбір` це показує (`ціна ← (100 + податок ← 20)`), але сам інтерпретатор мовчить. А `← x ＋ 1 / » 5 / » x` спершу **друкує 5** (побічна дія виконалася), а вже потім падає. Це класична вада Logo/REBOL-префіксу з фіксованою арністю без термінатора — і вона того самого класу, що «тихі збої» 0.1.
6. **Лексичні пастки — частково.** Виправлено: `n15` — статична помилка «невідоме імʼя»; ASCII `+ = -` дають підказку (`може, ＋?`). Лишилося:
   - змішані письма в числі: `＋ 1٢ 0` → **12**, `＋ 1 ٢3` → **24** — мовчки;
   - гомогліфи `ρ`/`р`, `κ`/`к`, `μ`/`µ` (U+00B5), `ʼ`/`’` ловляться лише як «невідоме імʼя/символ», без підказки (`µ` → «невідоме імʼя «µ»»); `−` (U+2212), `...`, `«` — теж без підказки;
   - у моєму ж розвʼязку Г рядок `μ ↑κсуми λк …` містить грецьке `κ` (гліф) і кириличне `к` (імʼя) поруч — для людини вони нерозрізнювані;
   - `¯5` на вході, але `» ¯5` друкує `-5`, а `ν 「¯5」` → помилка «не число»: власний літерал мови не проходить зворотного перетворення.
7. **Памʼятка без сигнатур — так, з прогалинами.** Сигнатури є, приклади працюють. Бракує: `§` на відсутньому ключі → `∅` (коштувало мені спробу в Г); що функцію, названу `←`, **не можна передати як значення** (див. нові вади, п. 2).
8. **`--розбір` — глосарій — так, виправлено.** Тепер справжній переклад: `суми ← згорнути оплачені, почавши з {}: (a, z) ↦ послідовно: …`, `було ← якщо (∅ = a[к]) то 0 інакше a[к]`. Це найкраща зміна 0.2.
9. **Ліміт кроків — так.** `ngr --кроки 10000 -e '… ☂ ↻ 0 λs ● λs ＋ s 1 λe 「перехоплено」'` → `✗ перевищено ліміт кроків`, `☂` його не перехопив.

## Нові вади 0.2

1. **Продовження виразу на наступний рядок без маркера** (п. 5 вище) — головна граматична вада. Правило «незавершений вираз продовжується» разом із тим, що `←` повертає значення, дає мовчазні неправильні програми. Forth/Joy цього не мають (стек видно), APL — бо рядок завжди закінчує вираз.
2. **Двоє сортів функцій, і розбір залежить від привʼязки імені.** Функція, названа `←`, завжди викликається: `μ 【1 2】 f` → «бракує аргументу»; `► f 4` → «бракує аргументу» (f зʼїв 4); `Σ 【1 2 3】 0 h` (h = `Λ`) → «бракує аргументу»; `← g f` зʼїдає наступний рядок і дає незрозуміле «g ще обчислюється: значення не може посилатися на себе». Передати іменовану функцію можна лише обгорткою `λx f x`. Немає аналога REBOL `:f` / Factor `\ f`. Наслідок: щоб розібрати `» f g 3`, читач (і модель) мусить памʼятати арність кожного імені користувача — дерево «відоме до запуску», але не з самого рядка.
3. **Впевненість контейнерів** (п. 4 вище) — ядро семантики «невпевненість як властивість значення» має дірку; `⚗`/`φ`/`ρ` над списком дають «певний» результат з непевних даних.
4. **Числовий друк втрачає інформацію:** `σ ＋ 0.1 0.2` → `0.3`, але `Δ` того ж → `0.30000000000000004`, а `＝ ν σ s s` → `○`. Два серіалізатори різняться; агент, що звіряє надрукований результат, отримає хибне «рівне».
5. **Дрібне в виразності:** функції лише 1–2 аргументів (`λ`, `Λ`); немає «належить до» / «значення за замовчуванням» для словника; групування за ключем — вручну через `Σ` і `✎`. Відповіді `⚗` у завданні В відірвані від питань (`【○ ●】`) — щоб зберегти пару, треба самому будувати словники.

Токени: виміряти `tiktoken` сам не зміг (запуск Python не дозволено в цій сесії), тож цифр SPEC §10 не перевіряв. За самим SPEC, без печатки 0.2 ≈ Python, з печаткою — дорожче; виграшу в щільності немає.

## Оцінки (1–10)
- Зрозумілість для ШІ-агента: 7 — чотири завдання за 5 запусків лише з памʼятки; дві пастки (`§`→`∅`, іменовані функції) у памʼятці не описані.
- Виразність: 6 — `μ φ Σ ↻`, словники, блоки, JSON достатні для звичних задач; бракує функцій вищої арності й першокласних іменованих функцій.
- Практична користь для реальної роботи агентів: 4 — справжні файли з дозволами власника працюють, але немає процесів, постійної памʼяті, а все, що дає мова (печатка, слід, впевненість), — властивості середовища виконання, не синтаксису.
- Прозорість для людини-власника: 8 — `--печатка` чітко показує, чого бракує в дозволах власника; `--розбір` — справжній переклад; слід зчеплений хешами. Мінус — гомогліфи в коді, що його бачить людина.

## Сильні сторони (до 3)
1. Префіксний запис з фіксованою арністю: без стека в голові, зайве в рядку — помилка до запуску; `--розбір` дає дерево з дужками.
2. Печатка + дозволи власника + `realpath`: `「файл.читати:../дані」` пройшов перевірку печатки, але `../дані/../дозволи.json` відхилено під час виконання.
3. Слід, який веде лише інтерпретатор: в агентному завданні кожен крок (делегування, інструмент, відсів, памʼять, перевірка) — окремий запис, ланцюжок перевіряється.

## Слабкі сторони (до 3)
1. Бракуючий аргумент мовчки поглинає наступний рядок — новий «тихий збій».
2. Впевненість відмивається через контейнери (`【v】`, `σ`, `ρ φ`) без `≈` і без сліду.
3. Розбір залежить від арності імен користувача; іменовані функції не першокласні.

## Пропозиції (до 5)
1. Продовження рядка — лише явне (відступ наступного рядка або гліф продовження); інакше кінець рядка завершує вираз, і бракуючий аргумент — помилка розбору. Заборонити `←` всередині виразу (воно повертає значення і мовчки визначає імʼя).
2. Впевненість контейнера = мінімум впевненостей елементів (або `＝ σ Δ ρ φ` над контейнером успадковують цей мінімум); `φ` — мінімум упевненостей умов.
3. Гліф «функція як значення» (на кшталт `:f` у REBOL), щоб `μ 【…】 :f` працювало без обгортки; у `--розбір` і повідомленнях показувати арність імен.
4. Лексер: число лише з цифр одного письма; підказки для `µ ’ − ... « »` і грецько-кириличних двійників (`ρ/р κ/к`); у `--розбір` позначати змішані письма.
5. У памʼятці: `§` на відсутньому ключі → `∅`; «іменовану функцію не можна передати як значення»; `σ` округлює числа (або зробити `σ` і `Δ` однаковими).
