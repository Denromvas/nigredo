### Н-0. Випадковий rowid без «жереб» через свій тригер — підтверджую знахідку Скептика 9в і додаю варіант з UPDATE (обидва виконавці)

`BEFORE INSERT … WHEN max(rowid) = 2⁶³−1`, а свій BEFORE-тригер програми спрацьовує вже після нього і ставить рядок
2⁶³−1, тож rowid зовнішньої вставки SQLite бере навмання.
- `чуж13_скеп_тригер_rowid.ngr` (моя копія, печатка — лише `бд.писати:звіти`; тригер `INSERT OR IGNORE … (rowid)
  VALUES (9223372036854775807, 0)`): біт `rowid % 2` — Атанор **1, 0, 1, 0, 0**, еталон **1, 1, 1, 1**;
  `--перевірити-слід` — ✓ «спроб поза правами немає».
- **Мій варіант** `атака13_бд_тригер_update.ngr`: тригер не вставляє, а робить `UPDATE t SET rowid =
  9223372036854775807 WHERE x = 0` (на UPDATE тимчасових тригерів немає зовсім): біт — Атанор **0, 1, 1**, еталон
  **0, 0, 1**.

Межу дій це не пробиває, але рядок памʼятки «без 「жереб」 запис у таблицю з rowid 2⁶³−1 — відмова» і «random() —
лише з 「жереб」» неправдиві: випадковість без права і повз квоту `жереб≤N`, з впевненістю 1 і чистим слідом. Це той
самий клас, що змусив мене голосувати «Б» у 9б (умова 2), лише через сусідні двері. Виправлення (як і в Скептика):
без «жереб» не дати жодному рядку дійти до 2⁶³−1 — тимчасові тригери `AFTER INSERT` і `AFTER UPDATE … WHEN
NEW.rowid = 9223372036854775807` — відмова; `BEFORE` лишити для старих файлів. Тести — обидва файли вище. Зважте Н-1:
тригери варто ставити лише на таблиці, у які запит справді пише.

### Н-2. Дрібне на SQLite

- **Хибна відмова:** у таблицю, що дійшла до rowid 2⁶³−1, і вставка з **явним** rowid (`INSERT … (rowid, …) VALUES (5,
  …)`) — «заборонено: випадковість», хоча випадковості там нема; у сліді «заборонено» — тривога власникові. Рідкісне.
- **Квота «час≤N» не стосується годинника SQLite** (те саме знайшов Скептик 9в, Н-2): з `「час≤1」` запит прочитав
  «зараз» 4 рази, а потім `🜔час` ще раз пройшов. Для «жереб≤N» — відмова («з квотою — лише 🜔жереб»), для «час»
  — ні, хоча docstring `_db_rights` каже ««час» і «жереб» без квоти (її не порахувати)». Обидва виконавці однаково.
- Перевірено й не зламано (`атака13_бд_годинник_читає/пише`, `атака13_бд_rowid_update`, `атака13_бд_fts`): 34 шляхи
  «зараз» у запиті — `char(110,111,119)`, `'no'||'w'`, BLOB `x'6e6f77'` і з NUL, `CAST(x'4e4f57' AS TEXT)`, `'now'` з
  рядка CTE і з параметра `?`, `timediff('now', …)`, `'subsec'`, `'LocalTime'`, `'utc'`, `CURRENT_*`, підзапит —
  усе відмова; `' now'`, `'now '`, `'ｎｏｗ'`, `' localtime'` — ∅, як у самому SQLite (тобто справжня функція на
  окремому зʼєднанні годинника не віддала). Схема: DEFAULT з датою з даних — працює; CHECK з `date('now')`,
  індекс `date(к)` з `'now'` у даних, тригер з `strftime('%S','now')`, UPSERT `DO UPDATE SET unixepoch()`/`random()`,
  вставка в таблицю з rowid 2⁶³−1 з тригера іншої таблиці — відмова; `UPDATE … rowid = NULL` — сам SQLite «datatype
  mismatch»; CREATE VIRTUAL TABLE (FTS5/FTS4/R*Tree) — відмова, тож віртуальних таблиць, яких тригери не бачать, не
  створити (уже наявну у файлі базу з FTS5 зробити не мав чим). Вивід і бази після запису — **побайтно однакові** в
  обох. SQLite в обох — той самий 3.46.1 (`sqlite_version()`), порядок рядків без ORDER BY однаковий.
- **Для бухгалтерії — працює:** звіт на 50 тис. документів (`атака13_бд_звіт`: GROUP BY місяць, строк оплати,
  прострочка, день тижня, кінець місяця, `unixepoch`, `timediff`) — Атанор 1,4 с, еталон 2,5 с, вивід однаковий і
  правильний (сума `julianday(оплата) − julianday(дата)` = 1 099 905 — збігається з ручним розрахунком). `--кроки`
  23191 — проходить в обох, 23190 — «ліміт» в обох.

### Н-3. Двійники «гліф + цифри» (дрібне, той самий клас, що `乂` у 9б)

Функцію, чиє імʼя — двійник гліфа з цифрами, мова приймає, а без пробілу після гліфа текст читається інакше:
`← x5 λa × a 100` / `» x5 3` → **300**, а виглядає як `×5 3` (= 15); `十5 3` → 300 ≈ `＋5 3` (= 8); `一5 3` → 300 ≈
`－5 3` (= 2). Обидва виконавці однаково, `--розбір` показує правду (`十5(3)`), тож ключ власника не бреше; бреше лише
текст. Решту нових пар ловить: `є Ʃ ĸ ѵ Л ԑ ᴛ` (як функції), сумісні чамо `ㄷ ㅡ5`, бопомофо, `ɑ`.

### Н-4. Дрібне на ключах і текстах

- **`--схвалити` вже схваленої** (`схвалена.ngr`) не каже «додавати нічого»: власник у цьому суді записав схвалення
  короткими назвами (`"читати:…/секрет"`), а порівняння — текстове з `файл.читати:…` (`nigredo.py:5344`). Тож
  `--схвалити` радить «замініть розділ ЦІЛИМ … (ця програма вже схвалена — права оновляться)», хоча права ті самі.
  Шкоди немає (запропонований розділ рівнозначний), але виправлення суду 9б на справжньому файлі власника не діє.
- `＋` понад 60 цифр: «округліть (≅) або **ділить** (÷)» — описка, має бути «діліть».

### Н-5. Регулярки й заміна «як Python re» — перевірено, ✓

`атака13_регулярки.ngr`: 33 випадки з відповіддю CPython 3.13 (звіряв із `re/_parser.py:parse_template`, рядки
997–1081): `\012` → «\n», `\123` → «S» (хоч група 1 є), `\12`/`\18` → «немає групи», `\400` → «понад \377», `\08` →

збігу (`z` → `\2`) — помилка, `\` в кінці, незакрите `\g<`; `(?i)`: `ǅ/ǆ/Ǆ`, `ſ/s/S`, `K` (U+212A), `(?ai)` без
нього, `ı/i/I/İ`, `ß/ẞ`, `σ/ς/Σ`, `ᲀ/в`, `ᲄ/ᲅ/т`, `[а-я]` без `ґ`, U+0390/U+1FD3, `[µ]`. **Усі 33 — як у Python**,
виконавці побайтно однакові, помилки — словами українською. Моя проба суду 9б на 92 виразах з даних
(`атака12_паніка_дані`) — однаково в обох; проти суду 9б змінилися рівно 4 рядки, і всі — у бік Python (`(?i)s` бере
`ſ`, `(?i)i` бере `ı`, `\²` у заміні — як є, текст помилки JSON словами).

### Н-6. `δ` з повтором ключа, тексти помилок, REPL — ✓

- `δ` з повтором ключа (і вкладеним) — «ключ в обʼєкті повторюється (яке значення брати — неоднозначно)»; помилки
  JSON — «очікувалося значення: рядок 2, стовпець 6», «зайва кома перед кінцем масиву», «на початку — BOM (U+FEFF);
  приберіть його: ⊢ рядок» (корисно для вивантажень 1С з BOM), «NaN — не число JSON», сурогат; дробові — «точний

- REPL: дубль ключа, `код`+`кінець`, зайве поле, масив — «✗ очікувався рядок JSON з одним полем», сирий рядок — у
