# Мовознавець — повторний огляд 0.4.3, раунд 2

## 1. Заморожено?

`sha256sum` поза моєю текою пісочниця знову не пустила, тож перевіряв двома незалежними способами:
```
git cat-file -p HEAD:interpreter/nigredo.py | sha256sum   → e991b390…e1b3251   (= ПРАВИЛА)
git cat-file -p HEAD:mcp/nigredo_mcp.py     | sha256sum   → 566ab02a…273fcb    (= ПРАВИЛА)
git status --short …/interpreter …/mcp                    → порожньо;  git log -1 → e650d9d
ngr …/interpreter/nigredo.py --слід -   (sha256 сирих байтів робочої копії) → e991b390…e1b3251
```
Версія та сама, що в раунді 1. Хеші за Новачка (його сесія не дала їх порахувати) — збігаються.

## 3. Погляд мовознавця на все, що лишилося

Вісім відкритих знахідок (мої 6.2, 6.3, 6.6, 6.7 і чужі 1, 3, 5, 7 вище) — це **одна вада, розкидана по
п'яти місцях**. У мові немає єдиного поняття «видимий символ». Натомість є п'ять різних фільтрів:

| Де | Що відкидає / показує | Чого не ловить |
|---|---|---|
| імена (лексер) | `Cc Cf`, заповнювачі, нестандартні пробіли, змішані письма, 29 пар `CONFUSABLE` | `һ ԁ ӏ ɡ օ 𝚡 ｘ`, `ʼ`/`'`, імʼя ≈ гліф / цифра |
| печатка (`plain_text`) | `Cc Cf Zl Zp Co Cn Cs` | U+034F, U+3164, U+115F, U+2800, U+FE0F, U+3000, пробіли поспіль, `« » /` в іменах субагентів |
| шляхи `файл.*` | керівні символи | ті самі невидимі, що й у печатці |
| коментарі й рядки коду | нічого | CR, ESC, U+2028, RLO (мій 6.7) |
| слід / MCP | слід: нічого (`ensure_ascii=False`); MCP: C0, C1, BIDI | U+2028/U+0085 ламають перевірку; теги U+E00xx, ZWSP доходять до LLM |

В APL і Forth такої проблеми немає лише тому, що вони живуть в ASCII чи власній кодовій таблиці. Nigredo свідомо
взяла весь Unicode (гліфи, CJK-дужки, алхімію), тож мусить мати **одне правило видимості як частину граматики**, а
не латки за знахідками судів. Пропоную формально (у SPEC):

- `невидиме(c)` := `General_Category ∈ {Cc, Cf, Zl, Zp, Co, Cn, Cs}` ∨ `Default_Ignorable_Code_Point(c)` ∨ `c` — заповнювач
  (U+115F, U+1160, U+3164, U+FFA0, U+2800) ∨ (`Zs` ∧ `c ≠ U+0020`), за винятком `\n \t` там, де їх дозволено.
- Одне правило на п'ять місць. В імені, печатці, шляху, коментарі й сирому рядку коду — помилка розбору.
  Із даних (`δ`, `файл.читати`) — допустимо. У слід і MCP — лише екрановано (` `, `⟨U+…⟩`).
- Тотожність імен — скелет UTS #39 після NFKC. Його так само порівнювати з гліфами (`ρ ν κ φ × Σ`) і з цифрами.
  Числа — лише ASCII-цифри: «цифри одного письма» з памʼятки (рядок 15) пропускають `০.৪`, що читається як «0.8».

Це не лише безпека, а й **однозначність читання**. Мова, яку агенти читають як текст, має гарантувати, що два
різні дерева не дають однакового тексту на екрані. Зараз це гарантовано для структури (префіксний запис, фіксована
арність), а для лексики — ні.

Окремо, **ортогональність `☠` і `🜍`**. `¿ x ☠ … ∅` ≡ `🜍 x λu ¬u` за змістом, а за впевненістю вони різні. Це
неортогональність примітивів, яку видно статично. Правило «керування під сумнівною умовою, у гілці якого досяжна
неперехоплена помилка, знижує решту запуску» закриває всі варіанти з таблиці 8 (`☠`, `÷ 0`, `§`, `ν`, ліміт кроків).

## 4. Остаточний голос

```
А — Nigredo стає спільною мовою агентів для програм, які агенти передають одне одному / виконують від імені власника
Б — лишається експериментальною
В — не потрібна
```

**Мій голос: А** — для ніші «доручення з печаткою і слідом», не як мова загального призначення.

Обґрунтування. Мірило для «А» з суду 5 у мене й у решти було однакове: межа дій, правдивий вердикт печатки,
правдивий слід. Раунд 2 його не похитнув. Я відтворив десять найсерйозніших чужих тверджень, і всі вони правдиві. Але
жодне не виводить за печатку чи дозволи власника і не дає хибного `✓`. Помилка сліду (рядок 1) іде в безпечний бік:
«✗» замість «✓». Межу дозволів власника не пробито на двох заморожених версіях поспіль, а межу субагентів (пробиту в
суді 5) закрито, і 30+ нових обхідних шляхів від шести учасників її не пройшли. Те, що лишилося, — шар **видимості
лексики**, а не модель прав. Він лагодиться однією функцією замість п'яти фільтрів.

Умови (кожна з негативним тестом; нового суду не треба, досить перевірки виправлень):

1. **До реального використання** (б'ють саме по ніші «печатка + слід»):
   - а) `verify_trace` — `split('\n')` замість `splitlines()`, а в сліді екранувати U+2028/2029/0085. Без цього «✗» не
     означає втручання (рядок 1);
   - б) MCP `clean` і показ печатки — те саме правило `невидиме()` (теги, ZWSP, заповнювачі → `⟨U+…⟩`). Інакше лишається
     невидимий канал від автора програми до LLM-виконавця, повз очі власника (рядки 3, 5);
   - в) в іменах субагентів — без `/`, а `«»`/намір у текстовому звіті екрановані; у дозволах — без пробілів поспіль (рядок 7, мій 6.2).
2. Скелет двійників за UTS #39 + NFKC, порівнювати також із гліфами й цифрами; числа лише ASCII. Доки цього немає,
   SPEC §9б має обіцяти «найчастіші кирилично-латинські двійники», а не «двійники між письмами — помилка».
3. Керівні символи в коментарях і сирих рядках коду — помилка (мій 6.7).
4. `☠` і помилки під сумнівним керуванням — як `🜍`. Або хоча б описати канал у `--памʼятка-коротка` (MCP).
5. `--перевірити-слід` пише кількість «заборонено», аргументи й теку. Вивід понад 4000 символів — повністю в сліді
   (у межах `--слід-розмір`) або чесно в SPEC §7. Опис MCP `nigredo_pechatka`: «необхідно, але не досить», а не «цього досить».
6. Дрібне: `--слід` лише поза теками власника й теками з `для_тек`; `BrokenPipe` → тихий вихід, а не код 4; `права теки`
   для теки запису → «немає»; `--печатка --json` при помилці розбору — теж JSON.

Мій голос стає **Б**, якщо умову 1 не виконають до того, як Nigredo почнуть використовувати для реальних доручень.
Слід, який чесні дані роблять «пошкодженим», і невидимий канал до LLM-виконавця суперечать самій ніші.
