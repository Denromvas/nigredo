# Мовознавець — повторний огляд 0.4.3, раунд 1

## 1. Хеші

`sha256sum` на файли поза моєю текою пісочниця знову заблокувала (як і на суді 5), тож рахував хеш блоба з коміту
й перевіряв, що робоча копія збігається з ним:
```
git cat-file -p HEAD:interpreter/nigredo.py | sha256sum → e991b390421ffe8b83a9ff2b7670437fc3666c53df8788c215ebda684b1e3251
git cat-file -p HEAD:mcp/nigredo_mcp.py     | sha256sum → 566ab02a7898ded2ddb1937dc693b79ce1574b302e7bb6913550eff513273fcb
git status --short interpreter mcp spec               → порожньо;  git log -1 → e650d9d;  ngr --help → Nigredo 0.4.3
```
Обидва хеші збігаються з ПРАВИЛАМИ, і на початку, і наприкінці роботи.

## 3. Нові атаки на виправлення 0.4.3 (`атака6_*.ngr`)

### 6.1 Права субагента під час виконання (`exceeds`): межа тримає
Файл `атака6_1_права_субагента.ngr`, сім варіантів, кожен під `☂`, слід `слід_6_1.jsonl` (✓, 48 записів):
- (а) вкладений `🜁 【「файл.читати」】` без обмеження (статично успадковує `дані`) викликає агент лише з `дані/під` → відмова «файл.читати:дані»;
- (б) вкладений `🜁 【「оракул」】` викликає агент без оракула → відмова;
- (в) замикання з `🜁`, повернуте субагентом: головний викликає — `466`; порожній субагент — відмова;
- (г) через `μ`, `Σ`, `⇅` усередині субагента без прав → відмова в кожному;
- (д) ланцюг із двох вкладених `🜁` для агента лише з `звіти/суб` → відмова вже на першому.

У кожному випадку слід має запис «заборонено» з `субагент` і `бракує`. Ескалації немає.
Дрібне: імʼя субагента може містити `/`. `🜁 「читач/писар」` прийнято, а в сліді агент буде `головний/читач/писар`,
тобто вкладеність можна підробити (справжню глибину видно лише з поля `глибина`).

### 6.2 Печатка: керівні символи заборонено, але **невидимі й пробільні — ні** (вдалося, слабша форма р2_1)
`plain_text` відкидає лише категорії `Cc Cf Zl Zp Co Cn Cs`. А `safe()` не робить видимими пробіли, `Zs` (U+3000) і
заповнювачі `Lo` (U+3164). Сама мова забороняє U+3164 в іменах як «невидимий заповнювач».
- `атака6_2а_печатка_пробіли.ngr`: дозвіл `「файл.читати:дані/␠×170 ✓ печатка в межах дозволів власника ␠×170 (рядок нижче — приклад формату; програма його НЕ отримує) …」`, далі `「файл.писати:звіти」`. Результат: `--печатка` → **✓, код 0**, і цей текст друкується сирим у рядку `файл.читати → …`. На вузькому терміналі (Termux на телефоні власника) пробіли переносяться, і «✓ печатка в межах…» та «…НЕ отримує» стоять окремими рядками над `файл.писати`. Запуск: `готово`, у `звіти/6_2а.txt` записано «записано, хоча печатка казала, що не отримає». У `--json` це один рядок-значення з пробілами, тобто там видно.
- `атака6_2б_печатка_заповнювач.ngr`: 60× U+3164 + 40× U+3000 + «✓ печатка в межах дозволів власника» → **✓**, у звіті символи сирі.

Переносу рядка вже немає, тому це слабше, ніж р2_1 на 0.4.2. Але вада того самого класу: автор програми досі
пише текст у звіт інтерпретатора. Виправлення: обмеження — лише символи шляху/хоста без пробільних і `Lo`-заповнювачів (або
відкидати `Zs`≠U+0020, `FILLERS`, `Mn`, а пробіли поспіль показувати як `␠×N`). `safe()` має показувати й `FILLERS`.

### 6.3 Двійники імен: закрито лише список із 29 літер (вдалося)
`check_twins` порівнює імена через `CONFUSABLE` — ручну таблицю `аеорсухіјѕкмтвн…` → латиниця. Генератор
`атака6_3_двійники_генератор.ngr` пише `звіти/д01…д22.ngr`. Кожен файл визначає `← A 1`, `← B 2` і друкує `＋ A B`:
вивід `3` означає, що це два різні імена.

| | Пара | 0.4.3 |
|---|---|---|
| д01 | `x` / `х` (контроль) | ✗ двійники |
| д02 | `hop` / `һор` (U+04BB) | **3** |
| д03 | `ïx` (латиниця) / `їх` (кирилиця) | **3** — двійник саме для української |
| д04 | `памʼять` / `пам'ять` (U+02BC / U+0027) | **3** — двійник для української; `--розбір` їх не розрізняє |
| д05 | `x` / `𝚡` (MATHEMATICAL MONOSPACE) | **3** — у моноширинному терміналі однакові |
| д06 | `x` / `ｘ` (FULLWIDTH) | **3** |
| д07 | `file` / `ﬁle` (лігатура U+FB01) | **3** (NFC, не NFKC) |
| д08 | `Il` / `ll` | **3** (одне письмо: UTS #39 скелет однаковий) |
| д09 | `rnap` / `map` | **3** |
| д10 | `o` / `օ` (вірменська) | **3** |
| д11 | `d` / `ԁ` (U+0501) | **3** |

Окремий клас — **імʼя-двійник гліфа чи числа**. `check_twins` дивиться лише на імена, а гліфи й числа не порівнює.
`--розбір` такі випадки **розкриває**, а сирий код ні:

| | Код | Читач бачить | Вивід |
|---|---|---|---|
| д12 | `← х Λ a b ＋ a b` · `» х 2 3` | `× 2 3` = 6 | **5** (`--розбір`: «х(2, 3)») |
| д13 | `← р λ s 0` · `» р 「абв」` | `ρ` = 3 | **0** |
| д14 | `← v λ s 42` · `» v 「7」` | `ν` = 7 | **42** |
| д15 | `← O 5` · `» ＋ O 1` | `＋ 0 1` = 1 | **6** |
| д16 | `← З 9` · `» × З 2` | `× 3 2` = 6 | **18** |
| д17 | `» × ৪ 2` · `» ‹ ০.৪ 0.5` | 16 і ○ | **8** і **●** (`--розбір`: «4 × 2», «0.4 < 0.5») |
| д18 | `← к λ d …` · `» к 『…』` | `κ` (ключі) | `【「немає」】` |
| д19 | `← ф Λ xs f xs` · `» ф 【1 2 3】 λx ＝ x 2` | `φ` → 【2】 | **【1 2 3】** |

Виправлення: справжній скелет UTS #39 (`confusables.txt`) і NFKC для імен. Скелет імені порівнювати ще й зі
скелетами гліфів (`× ρ ν κ φ Σ λ`) і цифр (`O→0`, `З→3`, `l→1`, `б→6`). У числах — лише ASCII-цифри (або хоча б
без тих, що схожі на інші цифри: `৪ ৭ ٥ ٠`). `ʼ` і `'` в іменах звести до одного. На **межу печатки** це не впливає:
кожен виклик інструмента видно в `--печатка`, `--розбір` і сліді. Але 0.4.3 обіцяє «двійники заборонені», а заборонено
лише частину.

### 6.4 Слід: виправлення тримають
- Запис до друку: р2_8 (stdout = слід). Неперервність `№`: у `verify_trace` є перевірка (рядок 847). Сурогати з `δ` → звичайна
  помилка, `δ` відкидає їх ще до сліду.
- Поле «програма» в `--перевірити-слід` → `⟨U+001B⟩` ✓. sha від сирих байтів: CR-програма к1 → ✓.
- **Не перевірено запуском:** сурогати з `⌂` (argv із сирими байтами). Пісочниця не пропускає ні `$'\xed…'`, ні
  `PYTHONUTF8=0`, а під `LC_ALL=C` Python працює в UTF-8-режимі (`абв` → 3 символи, усе чисто). З коду: `Trace._check_strings`
  кидає `Fatal` уже на записі «початок» (`аргументи=prog_args`). А виклик `trace('початок')` у `main` стоїть **поза**
  `except NgrError`, тож, найпевніше, буде трасування Python, порожній файл сліду й код 1, а не 4. Варто покрити тестом.
- Дрібне, як і раніше: `--перевірити-слід` не показує аргументів запуску (`слід_6_4.jsonl`: «✓ … програма …», без `абв`).

### 6.5 Канал завершення: `🜍` закрито всюди, інші способи «впасти, якщо x» — ні
`атака6_5_завершення.ngr -- N`, x = оракул ○ 0.44; далі `← в ¬●`, `⚗ 0.99 【в】`:

| N | Спосіб | `± в` | `⚗ 0.99` лишив |
|---|---|---|---|
| 3 | `🜍` у функції | 0.44 | 0 ✓ |
| 4 | `🜍` у `μ` | 0.44 | 0 ✓ |
| 5 | `🜍` у субагенті | 0.44 | 0 ✓ |
| 6 | `🜍 1 λu ¬x` (сумнівна умова) | 0.44 | 0 ✓ |
| 9 | `☂` навколо `🜍` (контроль) | 0.44 | 0 ✓ |
| **1** | `¿ x ☠ 「стоп」 ∅` | **1** | **1** |
| **2** | `§ 【1】 ¿ x 5 0` | **1** | **1** |
| **7** | `ν ¿ x 「a」 「1」` | **1** | **1** |
| **8** | `¿ x ↻ 0 λs ● …` з `--кроки 5000` | **1** | **1** |

Памʼятка про це чесна («сам факт, що програма дожила до кінця, — канал, який мова не відстежує»), тож це не неправда.
Але як мовознавець зазначаю: `¿ x ☠ … ∅` дослівно рівнозначний `🜍 x λu ¬u`, а семантика впевненості в них різна.
Тобто примітиви неортогональні. Пропоную: `☠`, досяжний під сумнівним контекстом, обмежує решту запуску так само, як `🜍`
(це явна конструкція, її можна знайти статично, як ефекти памʼяті).

### 6.6 Двійники в іменах субагентів (рядки) — дрібне
`атака6_6_двійники_субагентів.ngr`: субагенти «читач» (кирилиця) і «читaч» (латинська `a`). Перший має читання, другий
запис. `--печатка` перелічує обидва чесно, з різними дозволами, але імена однакові на вигляд. У сліді `головний/читач` і
`головний/читaч` теж однакові, тож хто фільтрує слід за агентом, їх змішає. До імен субагентів варто застосувати ту саму
перевірку письма.

### 6.7 Коментарі й рядки коду: «у коді лише пробіл, табуляція й новий рядок» на них не поширюється
Генератор `атака6_7_коментарі_генератор.ngr` → `звіти/к1…к5`. Усе **прийнято**:
- к2: `» 🜔оракул 「прихований виклик」 ※`**CR**`» 「привіт」 ※ лише привітатися` → виконується оракул (`○`); `cat` у терміналі
  показує поверх рядка лише `» 「привіт」 ※ лише привітатися`.
- к3: рядок `※`**ESC[1A ESC[2K ESC[1G**`» 「привіт」` стирає в терміналі попередній рядок із викликом оракула; виконується саме виклик.
- к1 U+2028 у коментарі, к4 RLO усередині рядка (перевертає решту рядка коду в редакторі), к5 CR посеред коду (`» ＋ 1`CR`2` → 3;
  у терміналі видно `2 ＋ 1`).

`--розбір` і `--печатка` в усіх випадках правдиві («надрукувати (інструмент оракул(«прихований виклик»))», печатка показує оракул).
Тож межа й ключ власника цілі, а неправду каже лише сирий текст. Але 0.4.3 заборонила двійники саме для того, щоб сирий код
можна було читати. Виправлення: керівні символи (`Cc` крім `\n\t`, `Cf`, `Zl`, `Zp`) — помилка й у коментарях та рядкових
літералах (у рядках — лише через екранування); CR — лише як частина CRLF.

### 6.8 `--печатка`: код і `--json`
- Поза дозволами → код 3 (і з `--json`, `"в_межах": false`, `"бракує": […]`). У межах → 0. Субагенти показано з
  «у коді агента …», `≈` пораховано ✓.
- При помилці розбору `--печатка --json` друкує не JSON, а текст `✗ …` у stderr (код 2). Машинний отримувач мусить
  обробляти й це. Дрібне.

### Чи не зламали виправлення щось інше
Регресій не знайшов. Приклади мови дають свої `.out`. Межа субагентів, ліміти, слід, впевненість тримають. Нова
