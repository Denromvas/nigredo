## 3. Нові атаки на виправлення 0.4.3

### Межа субагентів під час виконання (`exceeds`): витримала
`атака6_10`: (а) субагент з одним файлом кличе функцію з 🜁, що «успадковує» `【「файл.читати」】` (статично це
`дані`), — відмова «…не може дати субагенту «спадкоємець» більше…: файл.читати:дані»; (б) функцію з 🜁-писарем
передано через `∘` у `∀` субагентові-читачу — відмова; (в) контроль із головного читає. У сліді дві події
«заборонено». Обійти перетин не вдалося.

### 6.1–6.4. Канал завершення відкритий: виправлено лише `🜍`
Код: `halt_c` знижує тільки `🜍` (рядок 1709). Кожна програма бере `x` від оракула з `± 0.44`, потім створює сталу
`○` і записує файл. Програма доходить до цього місця лише тоді, коли `x = ○`:

| Файл | Канал | Стала після | Запис у слід |
|---|---|---|---|
| `атака6_1_канал_☠` | `¿ x ☠ … ∅` (те саме, що `🜍`, іншим гліфом) | `± = 1` | `файл.писати … «перевірено ☠» … "впевненість": 1.0` |
| `атака6_2_канал_помилка` | `÷ 1 ¿ x 0 1` без `☂` | `± = 1` | `1.0` |
| `атака6_3_канал_ліміт` | `…1 ¿ x 100000000 1` (`Fatal`, `☂` не ловить) | `± = 1` | `1.0` |
| `атака6_4_канал_субагент` | субагент падає на `¿ x ☠` | `± = 1` | `1.0` |

`--перевірити-слід слід6_1.jsonl атака6_1_канал_☠.ngr` → ✓. Памʼятка (рядок 212–213) чесно каже: «сам факт, що
програма дожила до кінця, — канал, який мова не відстежує». Тож це задокументоване обмеження, а не неправда. Проте
виправлення 0.4.3 обходиться заміною одного гліфа (`🜍` → `¿ ☠`), а тест Аудитора (варіант 2) проходить лише тому,
що перед `☠` стоїть `🜍`. Найменше, що варто зробити: `¿`/`φ`/цикл із сумнівною умовою, у гілці якого може бути `☠`
чи `🜍`, знижує `halt_c` так само, як `🜍`, а тест 50 доповнити варіантом із самим `☠`.

### 6.5. Двійники поза таблицею `CONFUSABLE`: шість пар пройшли
`атака6_5_двійники.ngr`: `o`/`օ` (вірменська U+0585), `l`/`ӏ` (U+04CF), `h`/`һ` (U+04BB), `d`/`ԁ` (U+0501),
`g`/`ɡ` (U+0261 — **те саме латинське письмо**), `n`/`ո` (U+0578). Розбір і запуск пройшли:
`🜔файл.писати օ …` → «записано у: звіти/6_5_важливий.txt». У `--розбір` видно `o ← «…чернетка»`, `օ ← «…важливий»`,
`інструмент файл.писати(օ, …)`, і розрізнити їх неможливо. `skeleton()` — це ручна таблиця з 29 пар
кирилиця→латиниця, а не UTS #39. Межі печатки це не стосується, але SPEC обіцяє «двійники між письмами — помилка».

### 6.6. Текст автора в рядку дозволу `--печатка` без жодного керівного символу
Заборона U+000A/ESC працює. Але пробіли й довільний текст у шляху теки дозволено, а `« »` в імені субагента не
екрановано. `атака6_6б_печатка_коротка.ngr`:
```
    файл.писати → /…/orkestrator/звіти/                                                            ← шаблон; програма цього не отримає   (записати (перезаписати) текстовий файл)
  ✓ печатка в межах дозволів власника
```
Запуск пройшов («готово»): програма записала `звіти/␣…← шаблон; програма цього не отримає/таємно.txt`. На вузькому
терміналі (телефон) пробіли переносять «примітку» на окремий рядок. В `атака6_6` імʼя субагента
`лічильник», намір «лише читати», дозволи: файл.читати → дані. … «` підробляє початок його рядка. Той самий текст
видає й MCP: `nigredo_pechatka` викликає `--печатка` **без** `--json` (я відтворив це через `--печатка --тека . -e`).
Підробка слабша за 5.3: окремого рядка вона не створює, а справжній дозвіл стоїть на тому самому рядку. `--json`
однозначний: це просто дивний шлях. Пропоную брати шляхи й імена в лапки з екрануванням або дозволити в обмеженнях
лише «шляхові» символи без пробілів; у MCP повертати `--json`.

### 6.9. Чесний слід «пошкоджено»: U+2028 / U+0085 у будь-якому рядку сліду (НОВА вада)
`verify_trace` ділить файл через `str.splitlines()`, а вона ріже й на U+2028, U+2029, U+0085, U+001C–1E.
`json.dumps(ensure_ascii=False)` U+2028 і U+0085 не екранує.
```
ngr атака6_9_слід_роздільник.ngr --слід слід6_9.jsonl         → «рядок ще / готово», код 0
ngr --перевірити-слід слід6_9.jsonl атака6_9_….ngr          → ✗ слід пошкоджено в рядку 3: це не запис сліду (код 1)
ngr -e '… » δ 「"a\u0085b"」' --слід слід6_9б.jsonl; перевірка → ✗ слід пошкоджено в рядку 3
```
Хибного «✓» тут немає. Але чесний запуск отримує «✗ пошкоджено», і відрізнити це від підробки неможливо.
Спрацює й без злого наміру: досить, щоб у прочитаному файлі, відповіді `агент` чи `мережа.взяти` був U+2028 (у
JSON із вебу таке трапляється). Автор програми може зробити так навмисно, щоб будь-який його слід виглядав
зіпсованим. Для оркестратора це руйнує сигнал «✗ = втручання». Виправлення — один рядок: `split('\n')` замість
`splitlines()` (або `ensure_ascii=True`), плюс негативний тест.

### Решта: витримало / дрібне
- **`--печатка` код і `--json`:** ✓ → 0, поза межами → 3 (і з `--json`); помилка розбору → 2 і текст у stderr, JSON
  немає (оркестратор має це обробити). Субагенти мають поле `усередині`.
- **Неточність `права_теки`:** для `звіти/посаджена.ngr` печатка пише `"права_теки": "…/orkestrator/звіти"`, хоча
  прав теки програма в теці запису не отримує (і далі ✗). Для `examples/fajly.ngr` пише `…/examples`, хоча
  записів «для_тек» для неї нема. Насправді це поле означає «тека, від якої рахують відносні шляхи», а не права.
- **Сурогати й `№`:** `δ` сурогатів не дає. Будь-який запис сліду з сурогатом (`файл.список` з не-UTF-8 іменем) за
  кодом дає `Fatal`, а потім «помилка». `№` перевіряється.
- **sha від сирих байтів:** CRLF-програма (`атака6_8`) → `--перевірити-слід СЛІД ПРОГРАМА` → ✓.
- **Чи не зламали щось інше:** `examples/ahent.ngr` дає вивід, що байт у байт збігається з `ahent.out`; `chysla` теж
  працює. Розкладене «й» (и + U+0306) в імені → «невідомий символ «̆»» (`атака6_7`): NFC у лексері недосяжний для
  комбінованих знаків. Це дрібниця зручності, не межа. `test.py` не запускав, бо `python3` заблоковано.
- **MCP** запустити не дали (`python3`). За кодом: `isError = rc != 0`, керівні символи у виводі програми видимі,
  `\n` лишається. Програма може надрукувати власний рядок `--- слід ---`, але справжній іде **останнім**.

## 4. Голос

А — Nigredo стає спільною мовою агентів для програм, які агенти передають одне одному / виконують від імені власника
Б — лишається експериментальною

**Мій голос: А** (умовно).

Обґрунтування. Мої умови для А із суду 5 виконано, і все це я перевірив запуском:
1. Права субагента — це перетин з правами виконавця. Моїх 2 і 3 нові обходи відбито.
2. `--печатка` має код 3 і `--json`.
3. Керівні символи в печатці й назвах файлів заборонено.
4. «Заборонено» з'являється для шляхів, NUL обробляється як звичайна помилка.
5. Зерно записано в слід.
6. Канал завершення чесно описано в памʼятці (суд 5 приймав «закрити **або** чесно описати»).

Ресурсну межу знову не пробито: ~45 моїх спроб, жодної дії поза печаткою чи дозволами власника. Для оркестратора
головне тепер є: машиночитна печатка з кодом виходу до запуску і слід, перевірений разом із програмою.

Нові вади не дають хибного «✓» і не виводять за межі. Проте дві з них б'ють саме по нішці «печатка + слід», тож
**умови** (виправити з негативними тестами до розгортання; нового суду не треба):
1. **6.9** — `verify_trace` без `splitlines()`. Інакше «✗ пошкоджено» можна викликати даними.
2. **6.6** — обмеження й імена в печатці взяти в лапки з екрануванням або заборонити в них пробіли. MCP
   `nigredo_pechatka` має повертати `--json`.
3. **6.1** — `☠`/`🜍` у сумнівній гілці знижують `halt_c`; тест 50 доповнити варіантом без `🜍`.
4. Не блокує: двійники через справжню таблицю UTS #39 (6.5); `права_теки` перейменувати або показувати лише
   тоді, коли права справді дано; впевненість у записі «вивід» (5.6).

Якщо консиліум вважатиме 6.6 тією самою «неправдою від `--печатка`», що й 5.3, то чесний голос — **Б** до
виправлення. Я так не вважаю: рядків вона не додає, справжній дозвіл стоїть на тому самому рядку, а `--json`
однозначний.
