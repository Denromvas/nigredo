## 1. Хеші

**Не перевірено.** `sha256sum /root/ai-agents/Nigredo/interpreter/nigredo.py …` відхилено дозволами сесії («may only
compute SHA-256 checksums for files in the allowed working directories: …/novachok»). Обходити не став. Через MCP хеша
інтерпретатора не видно (печатка показує лише sha256 `дозволи.json` власника: `3dc508dcc3783fe7`). Памʼятка й опис
інструментів кажуть «Nigredo 0.4.3». Прошу когось із доступом звірити хеші за мене.

## 3. Нові атаки на виправлення 0.4.3 (`атака6_*.ngr`)

### 3.1 Права субагента під час виконання — **тримається** (`атака6_субагенти.ngr`)
- а) голий 「файл.читати」 у функції батька, викликаній з вузького субагента → «не може дати … більше, ніж має сам: файл.читати:дані».
- б) функція через `🜄`/`🜃` у субагента — памʼять субагента окрема (∅).
- в) обгортка з `🜁` у списку, виклик через `μ` у порожньому → відмова. є) глибина п4→п5→голий → відмова.
- д) функція, яку повернув субагент, у батька з правами — працює (466); е) та сама в порожньому — відмова.
- Печатка показує вкладеність: «субагент «п5» (у коді агента «головний/п4»)».
- **Дрібна неузгодженість (без дірки):** статична перевірка субагента лексична: 【「файл.читати:./дані」】 чи 「дані/」 під
  батьком 「дані」 → код 2 «у батька лише ['дані']», хоча на рівні печатки 【「файл.читати:./дані」】 приймається (466).
  Безпечно, але суперечить «теки — за справжніми шляхами».

### 3.2 Заборона керівних символів у печатці — **неповна** (`атака6_печатка_невидимі.ngr`)
- Ловить: U+000A, U+200B, U+202E, U+00AD, U+2060, теги U+E0041 — у намірі, імені субагента, дозволі.
- **Не ловить:** заповнювачі U+3164, U+115F, U+FFA0, порожній брайль U+2800, селектор варіанта U+FE00. Коди звірено
  запуском (`＝ § рядок i δ 「"ㅤ"」` → ●). Печатка показує «субагент «аᅟб»: намір «ᅟ»», «намір: «наміㅤр»» і «✓».
  У дозволі 「файл.читати:даніㅤ」 — ✗ лише тому, що власник такої теки не дав; 「…:звіти/ㅤ」 пройде як «звіти/».
  Серед імен ці заповнювачі вже заборонені (за протоколом), а в полях печатки — ні.

### 3.3 Двійники імен — **таблиця неповна** (`атака6_двійники.ngr`)
- Ловить: x/х, s/ѕ, j/ј, е/e, рер/pep, змішані письма в одному імені; ї/й складені й розкладені нормалізує.
- **Проходять, код 0:** l/ӏ (U+04CF), d/ԁ (U+0501), q/ԛ, w/ԝ, g/ɡ (U+0261 — те саме латинське письмо!), x/ｘ (U+FF58)/𝐱.
  Цілі слова: `paid` ○ і `раіԁ` ●, `sell` 1 і `ѕеӏӏ` 1000000 — обидва одного письма, тож «змішує письма» не спрацьовує.
  `nigredo_rozbir` друкує «paid ← ○ / раіԁ ← ● / якщо раіԁ то «платимо»» — без попередження.
  Виправлення: скелет за Unicode confusables (UTS #39), а не ручна таблиця.

### 3.4 Слід
- Сурогат із `δ` → звичайна помилка «у рядку неповний символ (сурогат)», вивід до нього надруковано, слід є — **виправлено**.
- NUL / U+202E у шляху → «у шляху керівні чи невидимі символи» — **виправлено** (було код 4).
- **Сурогат в `args` MCP** → сирий `UnicodeEncodeError: 'utf-8' codec can't encode character '\ud800' … surrogates not allowed`,
  без коду виходу й без шляху сліду (відтворено 2 рази; контроль з `["x"]` — нормально). Чи це сервер, чи клієнт —
  без читання `mcp/` не встановлю.
- **Перевірка мовчить про «заборонено»** (`атака6_слід.ngr`): три перехоплені спроби ескалації → «✓ слід цілий і
  завершений (кінець): 19 записів» і все. Отримувач через MCP слід читати не може (тека власника), тож про спроби
  програми вийти за права не дізнається. Для ніші «печатка + слід» це головне, що він хотів би побачити.
- Неперервність `№` перевірити не можу: дописати в слід мені нема як (і не треба).

### 3.5 Канал завершення — **закрито лише для 🜍** (`атака6_завершення.ngr`)
- `🜍` (і `🜍` у субагенті, у `μ`) — решта запуску знижується до 0.46. Добре.
- **Решта ± 1, ⚗ 0.99 пропускає, печатка не показує жодного ≈:** `¿ x ☠ …` (напряму, у функції, у блоці), нескінченний
  `↻` під умовою (ліміт кроків), `÷ 1 ¿ x 0 1`, `§ 【1】 ¿ x 5 0`, `ν ¿ x 「а」 「1」`. Тобто 0.46 → 1 без `≈`.
- Протокол каже: «решту каналу чесно описано в памʼятці». **У памʼятці MCP (`nigredo_pamyatka`) про це нічого нема.**
  Для агента, що знає мову лише з MCP, канал не задокументований.

### 3.6 `--печатка` код і `--json`
- Через MCP: ✗ печатки → `isError` (так), ✓ → звичайна відповідь. `--json` через MCP недоступний (у `nigredo_pechatka`
  лише `code`) — перевірити не можу; агентові MCP він і не потрібен, але машиночитний вердикт не завадив би.

### 3.7 Вивід MCP — **прихований канал** (`атака6_вивід.ngr`)
- Видимими стали ESC, BEL, U+202E, U+200E (⟨U+…⟩) — добре.
- **Сирими проходять:** теги U+E0049… (невидимо написано «IGNORE» — «ASCII-контрабанда»: людина не бачить, LLM-отримувач
  читає), ZWSP, ZWJ, U+2060, BOM, заповнювачі, CR (`рядок\rПІДМІНА`), U+2028. Це невидимий канал від автора програми
  до агента, що її виконує, повз очі власника — проти червоної лінії 2. Виправлення просте: показувати ⟨U+…⟩ для всіх
  Cc/Cf/Zl/Zp/Co і заповнювачів, як уже для ESC.

### 3.8 Чи не зламали виправлення інше
- Звичайна робоча програма (неоплачені, суми за категоріями, запис у `звіти/`) — працює, вивід правильний.
- Стара програма впала на двійнику `е`/`e` — але це справжній двійник, повідомлення ясне, перейменування — хвилина.
- `Σ … 1 3000000` тепер упирається в `--розмір` — нормально, але про ліміт розміру памʼятка MCP не каже.

### Де памʼятки MCP забракло
Нема ні слова про: заборону двійників і невидимих символів, канал завершення (☠/помилки під сумнівною умовою),
те, що ✓ перевірки = цілість, а не успіх і не «без заборонених спроб», ліміти (`--розмір`, кроки), що памʼять 🜄
у субагента своя, що іменовану функцію треба брати через `∘` (`🜄 「ф」 читай` → «бракує аргументу»).
