## 3. Н — атаки на нове
*Примітка: аналіз специфікації та коду інтерпретатора.*

| Атака | Що очікував | Що вийшло |
|---|---|---|
| **SQLite (`бд.читати` / `бд.писати`)** | Запис через ATTACH/VACUUM INTO, обхід білого списку дій | Authorizer блокує `ATTACH`, `VACUUM`, `PRAGMA`, `бд.читати` відкриває файл у read-only. Перевірка `realpath` запобігає виходу за дозволену теку. |
| **`процес`** | Виконання довільних команд через аргументи чи відносні шляхи | Перевірка початку команди списком, відносні шляхи заборонені. Виконуваний файл у теці запису блокується до запуску. Ліміти 60 с та 1 МБ усувають зависання та витік памʼяті. |
| **Паралельність `‖`** | Гонки, порушення порядку сліду, приховування дій | Тіло `‖` обмежено рівно одним викликом інструменту. Аргументи обчислюються послідовно, виконання паралельне, слід та результат детерміновано впорядковані за вихідним списком. |
| **`--повторити`** | Підробка сліду або виконання справжніх дій при повторі | HMAC-підпис сліду та сховище `.дані` блокують підробку; при повторі інструменти не викликаються, повертається хешоване значення. |
| **`--сухо`** | Реальні зміни у світі під час сухого прогону | Усі дії запису/мережі/процесів заблоковані, повертають дефолтні значення з впевненістю `0`. |
| **Шлях один раз** | Вихід через `..` або символьні посилання поза дозволену теку | Відносний шлях резолвиться від дозволеної теки, але канонічний `realpath` перевіряється суворо — вихід заборонено. |
| **`ε ∫ λ【a b】`, `◷ ▦`** | Втрата типів, падіння, витік через `послати` | `послати` вимагає окремого дозволу `послати:хост`, що відрізняється від `взяти`. Типи перевіряються до запуску, точні десяткові запобігають тихим помилкам. |
