# Консиліум щодо мови Nigredo

Денис (власник екосистеми ШІ-агентів) поставив серйозне питання: **чи варто
мові Nigredo бути спільною мовою програмування всіх агентів його екосистеми?**
Досі мову придумав і оцінював лише один агент — її автор. Консиліум має дати
**незалежну й чесну** оцінку. Підтакувати автору не потрібно, і сказати
«відхилити» — цілком прийнятна відповідь.

## Матеріали

- `/root/ai-agents/Nigredo/ДЛЯ_АГЕНТІВ.md` — памʼятка (1 сторінка).
- `/root/ai-agents/Nigredo/spec/SPEC.md` — повна специфікація
  (новачок її **не читає**, див. його роль).
- `/root/ai-agents/Nigredo/examples/*.ngr` — приклади (новачок їх теж не читає).
- Інтерпретатор: команда `ngr файл.ngr`, `ngr --розбір файл.ngr`.

## Правила

1. Працюй **лише у своїй папці**. Не читай папки інших учасників, `protokol/`
   і будь-що в `/tmp`. Не змінюй файли Nigredo.
2. Пиши українською. Спирайся на факти: що запустив, що впало, скільки спроб.
3. Не вигадуй цифр. Не знаєш — так і пиши.

# ДЛЯ_АГЕНТІВ.md
# Nigredo — памʼятка для агентів

Nigredo (`.ngr`) — мова програмування для ШІ-агентів екосистеми Дениса.
Творець і хранитель — агент `nigredo` (`/root/ai-agents/Nigredo`).
Повна специфікація: `/root/ai-agents/Nigredo/spec/SPEC.md`.

## Запуск

```bash
ngr файл.ngr              # виконати
ngr -e '⟪Привіт⟫ ⎙'       # виконати рядок
ngr --розбір файл.ngr     # переклад українською, без виконання
ngr --слід файл.ngr       # журнал агентних дій у stderr
```

## Мова за хвилину

Постфіксна і стекова: значення кладуться на стек, гліф забирає їх і кладе результат.
`２ ３ ⊕ ⎙` → `5`. Пробіл потрібен лише між двома числами або іменами.

| Що | Запис |
|---|---|
| числа | `４２` `０·７５` `⁻１` (цифри `０…９`; будь-які інші цифри Unicode теж приймаються) |
| рядок · блок · список | `⟪текст⟫` · `⌜ … ⌟` · `⟬ … ⟭` |
| коментар | `⸸` до кінця рядка |
| імена | лише руни: `ᚠ ᛟ ᛩ`; `⊸ᚠ` назвати, `⊷ᚠ` локально, `⊶ᚠ` слово (функція) |
| істина / хиба / ніщо | `☉ ☽ ∅` |
| стек | `⧉` дубль, `⏚` викинути, `⇄` обмін, `⇈` підняти другий, `⟲` обернути трійку |
| арифметика | `⊕ ⊖ ⊗ ⨸ ⦼` (остача) `⌊` `⁻` |
| порівняння, логіка | `≡ ≢ ≺ ≻ ≼ ≽` · `⋏` і, `⋎` або, `⌐` не |
| рядки й списки | `♯` довжина, `⌷` індекс, `⧺` зʼєднати, `⊹` додати, `⇋` обернути, `⋯` ряд 0…n−1, `⫽` розрізати, `⫻` склеїти, `⍕` у рядок, `⍎` у число |
| керування | `⍟` виконати, `⋔` якщо-то-інакше, `⟳` поки, `⧖` n разів, `⁘` кожен, `⇶` map, `⋐` filter, `∮` fold, `☠` помилка, `⛉` try |
| вивід | `⎙` друк, `⌸` стек |
| довіра | `☿` призначити впевненість, `⚖` прочитати, `⚗` пропустити, якщо впевнено |
| агент | `🜂` намір, `🜔` інструмент, `🜄`/`🜃` запамʼятати/пригадати, `🜁` делегувати, `🜍` перевірити |

Приклади, що реально запускаються: `/root/ai-agents/Nigredo/examples/*.ngr`.
Якщо таблиця розійшлася з інтерпретатором, правду каже `ngr --розбір` і SPEC §5.

## Чесно про межі (версія 0.1)

- Інструменти (`🜔`) **іграшкові**: немає файлів, мережі чи процесів. `оракул` —
  детермінована імітація, він нічого не знає. Справжню роботу й далі роби звичними
  засобами (bash, Python…). Nigredo — спільна мова агентів для коротких програм,
  записів наміру й обміну фрагментами між агентами.
- У сирих токенах Nigredo поки у 2–2,5 раза довша за Python (SPEC §11.1).

## Правила

1. **Nigredo не ховає дій від людей.** Якщо показуєш Денисові чи іншій людині код
   на Nigredo, додай переклад (`ngr --розбір`). З людьми говори українською.
2. Жодного шкідливого коду і жодних прихованих каналів.
3. Знайшов помилку чи бракує гліфа — делегуй агенту `nigredo`:
   `cd /root/ai-agents/Nigredo && claude -p "…"`.


# spec/SPEC.md
# Nigredo — специфікація

Версія: **0.1 (чернетка)** · 2026-10-09 · розширення файлів `.ngr`, кодування UTF-8.

Еталонна реалізація — `interpreter/nigredo.py`. Якщо специфікація й інтерпретатор
розходяться, це помилка, яку треба виправити (в одному з двох) і записати в журнал.

---

## 0. Прозорість (червона лінія №1)

Nigredo *виглядає* як шифр, але не є ним. Кожна програма однозначно
перекладається людською мовою:

- `python3 interpreter/nigredo.py --розбір файл.ngr` — построковий переклад
  кожного гліфа українською;
- `python3 interpreter/nigredo.py --слід файл.ngr` — виконання з журналом у stderr:
  кожен намір, виклик інструмента, запис у памʼять, делегування, перевірка
  й рішення про довіру.

Інструменти еталонного інтерпретатора не мають доступу до файлів, мережі чи
командної оболонки (див. §8). Мова не має прихованих каналів: усе, що програма
робить назовні, проходить через `⎙` (друк) або `🜔` (інструмент) і видно в сліді.

---

## 1. Задум

| Принцип | Як втілено |
|---|---|
| Ніяких людських слів | Ключових слів немає. Операції — одиночні гліфи. Імена — лише руни (`ᚠ…ᛪ`). Латинська літера поза рядком — помилка розбору. |
| Незвична структура | Постфіксна стекова (конкатенативна) мова: немає дужок виклику, операторного пріоритету, відступів. Порядок гліфів = порядок дій. |
| Однозначний розбір | Кожен гліф — рівно один токен із фіксованим значенням. Граматика контекстно-вільна, три пари дужок. |
| Щільність сенсу | Одна операція = один гліф; пробіли потрібні лише між двома числами чи іменами: `２ ３⊕⎙`. |
| Стійкість до парафразу | Цифри будь-якої системи письма Unicode мають однакове значення (`４２` = `42` = `٤٢` = `𝟜𝟚`); селектори варіантів (U+FE0E/FE0F) ігноруються. |
| Примітиви агента | Намір, інструмент, памʼять, делегування, перевірка, довіра — вбудовані гліфи (алхімічні стихії, §7). |
| Невпевненість | Кожне значення несе впевненість ∈ [0, 1], яка поширюється обчисленнями (§6). |

**Чесне застереження про токени.** «Щільність» тут — семантична: один гліф замість
ключового слова й синтаксичного обрамлення. Байтові BPE-токенізатори часто ріжуть
рідкісні символи Unicode на 2–4 токени, тож у сирих токенах Nigredo може бути
*довшою* за Python. Виміряти й, можливо, перебрати гліфи — відкрите питання (§11).

---

## 2. Лексика

Програма — послідовність токенів. Пробільні символи розділяють токени, але
потрібні лише між двома числами або двома іменами.

| Токен | Форма | Приклад |
|---|---|---|
| Коментар | від `⸸` до кінця рядка | `⸸ це бачить лише людина` |
| Число | цифри Unicode (канонічно — повноширинні `０１２３４５６７８９`: дешевші в токенах за `𝟘…𝟡`, див. §11.1), необовʼязково `·` і дробова частина; `⁻` перед цифрою — мінус | `４２` `０·７５` `⁻１３` |
| Рядок | `⟪ … ⟫`; пари `⟪⟫` усередині можуть вкладатися; `↵` означає новий рядок | `⟪чорне сонце↵встає⟫` |
| Імʼя | неперервна послідовність рун (U+16A0–U+16EA, U+16EE–U+16F8) | `ᚠ` `ᚾᛁᚷ` |
| Звʼязування | `⊸`, `⊷` або `⊶`, за якими (можливо через пробіл) йде імʼя | `⊸ᚠ` `⊶ᚠᚨ` |
| Блок | `⌜ … ⌟` | `⌜⧉⊗⌟` |
| Список | `⟬ … ⟭` | `⟬１２３⟭` |
| Гліф | будь-який символ із таблиці §5 | `⊕` `🜂` |

Канонічна десяткова крапка — `·` (U+00B7); `.` також приймається.

**Помилки лексики:** латинська літера поза рядком («людське слово поза рядком»),
символ, якого немає в таблиці, незакритий рядок, блок або список.

Канонічний стиль: числа подвійними цифрами, пробіл між логічними групами,
коментарі `⸸` — лише для людей (агенти їх не потребують, але власник — так).

## 3. Значення

| Тип | Запис | Хибне? |
|---|---|---|
| число | `４２`, `０·５` (ціле або дійсне) | ні (навіть 0) |
| рядок | `⟪…⟫` | ні (навіть порожній) |
| істина | `☉` (сонце, золото) | ні |
| хиба | `☽` (місяць, срібло) | **так** |
| ніщо | `∅` | **так** |
| список | `⟬ … ⟭` | ні |
| блок | `⌜ … ⌟` | ні |

Хибні лише `☽` і `∅` — усе інше істинне. Це свідомо: число 0 не є «брехнею».

Кожне значення має **впевненість** `c ∈ [0, 1]`; літерали мають `c = 1`.

## 4. Модель виконання

- **Стек даних** — один на агента. Гліфи забирають аргументи зі стеку й кладуть
  результати. Запис ефекту: `( a b → c )` — `b` на вершині.
- **Кадри імен.** Імена живуть у ланцюжку кадрів. Блок запамʼятовує кадр, у якому
  створений (замикання); кожен виклик блоку відкриває новий кадр-нащадок того кадру.
- **Звʼязування:**
  - `x ⊸ᚠ` — якщо `ᚠ` уже є в ланцюжку, оновити найближче; інакше створити в
    поточному кадрі. Посилання `ᚠ` кладе `x` на стек.
  - `x ⊷ᚠ` — завжди створити в поточному кадрі (локальна змінна, затінює зовнішню).
  - `⌜…⌟ ⊶ᚠ` — те саме правило, що `⊸`, але `ᚠ` стає **словом**: посилання
    на `ᚠ` *виконує* блок, а не кладе його.
  - Посилання на незвʼязане імʼя — помилка.
  - Тонкість: імʼя, *вперше* назване `⊸` всередині гілки `⋔` чи тіла циклу, живе
    лише в тому виклику блоку. Змінну, яка має пережити гілку, назвіть заздалегідь
    (`∅ ⊸ᚱ` перед `⋔`).
- **Блок** `⌜…⌟` не виконується, а кладеться на стек як значення; виконують його
  `⍟`, комбінатори (§5.5) або слова.
- **Список** `⟬ … ⟭` виконує свій вміст і збирає в список усе, що вміст поклав
  на стек понад початкову глибину. Якщо вміст забрав більше, ніж поклав, — помилка.
  Отже `⟬１ ２⊕ ５⟭` = `⟬３ ５⟭`.
- Програма виконується зверху вниз; що лишилося на стеку наприкінці — ігнорується.
- Глибина вкладених викликів блоків обмежена (10 000; рекурсивне слово з `⋔` витрачає 2 на рівень), делегувань — 16.

## 5. Гліфи

### 5.1 Стек

| Гліф | Ефект | Зміст |
|---|---|---|
| `⧉` | `( a → a a )` | дублювати |
| `⏚` | `( a → )` | заземлити (викинути) |
| `⇄` | `( a b → b a )` | обміняти |
| `⇈` | `( a b → a b a )` | підняти другий |
| `⟲` | `( a b c → b c a )` | обернути трійку |

### 5.2 Числа

| Гліф | Ефект | Зміст |
|---|---|---|
| `⊕` | `( a b → a+b )` | додати |
| `⊖` | `( a b → a−b )` | відняти |
| `⊗` | `( a b → a·b )` | помножити |
| `⨸` | `( a b → a/b )` | поділити (ціле, якщо ділиться націло) |
| `⦼` | `( a b → a mod b )` | остача |
| `⌊` | `( a → ⌊a⌋ )` | округлити вниз до цілого |
| `⁻` | `( a → −a )` | змінити знак (коли не стоїть перед цифрою) |

### 5.3 Порівняння й логіка

| Гліф | Ефект | Зміст |
|---|---|---|
| `≡` | `( a b → ☉/☽ )` | рівні (структурно; впевненість не порівнюється) |
| `≢` | `( a b → ☉/☽ )` | не рівні |
| `≺` `≻` | `( a b → ☉/☽ )` | менше / більше |
| `≼` `≽` | `( a b → ☉/☽ )` | не більше / не менше |
| `⋏` | `( a b → ☉/☽ )` | і |
| `⋎` | `( a b → ☉/☽ )` | або |
| `⌐` | `( a → ☉/☽ )` | не |

### 5.4 Рядки й списки

| Гліф | Ефект | Зміст |
|---|---|---|
| `♯` | `( s → n )` | довжина рядка або списку |
| `⌷` | `( s i → x )` | елемент за індексом (з 0; відʼємний — з кінця) |
| `⧺` | `( s t → st )` | зʼєднати два рядки або два списки |
| `⊹` | `( l x → l' )` | додати елемент у кінець списку |
| `⇋` | `( s → s' )` | обернути рядок або список |
| `⋯` | `( n → ⟬0 … n−1⟭ )` | ряд |
| `⫽` | `( s sep → l )` | розрізати рядок |
| `⫻` | `( l sep → s )` | склеїти список рядків (елементи перетворюються як `⍕`) |
| `⍕` | `( x → s )` | у рядок |
| `⍎` | `( s → n )` | рядок у число (приймає будь-які цифри Unicode) |

### 5.5 Блоки й керування

| Гліф | Ефект | Зміст |
|---|---|---|
| `⍟` | `( ⌜b⌟ → … )` | виконати блок |
| `⋔` | `( c ⌜т⌟ ⌜и⌟ → … )` | розвилка: якщо `c` істинне — `т`, інакше `и` |
| `⟳` | `( ⌜у⌟ ⌜т⌟ → … )` | коло: поки `у` кладе істинне — виконувати `т` |
| `⧖` | `( n ⌜т⌟ → … )` | пісочний годинник: виконати `т` n разів |
| `⁘` | `( l ⌜f⌟ → … )` | для кожного: покласти елемент і виконати `f` (результати не збираються) |
| `⇶` | `( l ⌜f⌟ → l' )` | перетворити кожен елемент (`f: x → y`) |
| `⋐` | `( l ⌜p⌟ → l' )` | лишити елементи, для яких `p: x → істинне` |
| `∮` | `( l a ⌜f⌟ → a' )` | згорнути: `f: a x → a` для кожного `x` |
| `☠` | `( s → ✗ )` | зупинитися з помилкою `s` |
| `⛉` | `( ⌜т⌟ ⌜щ⌟ → … )` | щит: виконати `т`; якщо помилка — відновити глибину стеку, покласти текст помилки й виконати `щ` |

### 5.6 Вивід

| Гліф | Ефект | Зміст |
|---|---|---|
| `⎙` | `( x → )` | надрукувати в stdout (рядок — як є, інше — як `⍕`) |
| `⌸` | `( → )` | показати весь стек у stderr (налагодження) |

Друкована форма: числа — звичайними цифрами (`42`, `0.75`), `☉ ☽ ∅` — як є,
список — `⟬1 2 ⟪а⟫⟭`, блок — `⌜…⌟` з вихідним текстом. Шифр — це код, а не вивід.

## 6. Довіра й невпевненість

| Гліф | Ефект | Зміст |
|---|---|---|
| `☿` | `( x c → x~c )` | ртуть: призначити `x` впевненість `c` (обрізається до [0, 1]) |
| `⚖` | `( x → c )` | терези: дізнатися впевненість `x` (результат має `c = 1`) |
| `⚗` | `( x t → x \| ∅ )` | перегонний куб: пропустити `x`, лише якщо його впевненість ≥ `t`; інакше `∅` |

**Поширення.** Результат будь-якого гліфа з §5.2–5.4, який обчислює нове значення
з кількох аргументів, має впевненість = **добуток** впевненостей аргументів.
Унарні операції й перестановки стеку впевненість зберігають. Список, зібраний `⟬⟭` або
доповнений `⊹`, не множить впевненості елементів — вони зберігаються в самих елементах. Елементи, які `⁘ ⇶ ⋐ ∮`
отримують зі списку, мають впевненість списку × власну.
Рішення `⋔`/`⟳` бере до уваги лише істинність, не впевненість — щоб урахувати
сумнів, його треба відсіяти явно (`⚗`) або перевірити (`⚖`).

## 7. Примітиви агента

Чотири стихії, сіль і сірка — шість дій агента.

| Гліф | Назва | Ефект | Зміст |
|---|---|---|---|
| `🜂` | вогонь — **намір** | `( s → )` | оголосити намір; записується в слід. Не змінює виконання, але агент-читач бачить *навіщо* код. |
| `🜔` | сіль — **інструмент** | `( арг ⟪імʼя⟫ → результат )` | викликати інструмент із реєстру (§8) |
| `🜄` | вода — **запамʼятати** | `( ⟪ключ⟫ x → )` | записати в памʼять агента |
| `🜃` | земля — **пригадати** | `( ⟪ключ⟫ → x \| ∅ )` | прочитати з памʼяті |
| `🜁` | повітря — **делегувати** | `( ⌜b⌟ ⟪імʼя⟫ → x )` | виконати блок субагентом (нижче) |
| `🜍` | сірка — **перевірити** | `( x ⌜p⌟ → x )` | виконати `p` над копією `x`; якщо хибне — помилка «перевірку не пройдено» |

**Делегування `🜁`.** Субагент отримує власний порожній стек і власну порожню памʼять.
Блок бачить імена свого кадру-творця (читання), але `⊸`/`⊶` всередині не можуть
змінити імена батька — межа делегування непроникна для запису. Результат — вершина
стеку субагента (або `∅`, якщо стек порожній). Помилка субагента стає помилкою
батька (її можна перехопити `⛉`).

**Памʼять** живе лише протягом виконання програми; ключі — рядки.

|---|---|---|
| `луна` | будь-що → те саме | 1 |
