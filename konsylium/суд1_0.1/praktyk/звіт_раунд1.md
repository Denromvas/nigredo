# Практик

Читав: `ДЛЯ_АГЕНТІВ.md`, `spec/SPEC.md` повністю, `examples/ahent.ngr`, `examples/chysla.ngr`.
Без прикладу `ahent.ngr` завдання В я б писав довше — шаблон делегування
`⌜ ⊷ᛩ ⌜ ᛩ ⟪оракул⟫ 🜔 ⌟ ⟪…⟫ 🜁 ⌟ ⊶ᛟ` я фактично взяв звідти.

## Завдання
| | Вийшло? | Спроб | Головна складність |
|---|---|---|---|
| А. FizzBuzz | так | 1 | Три вкладені `⋔` з блоками: закривальні `⌟ ⋔ ⌟ ⋔ ⌟ ⋔` доводиться рахувати в голові. `⋯` дає 0…n−1, тож `１ ⊕` на початку. |
| Б. Рядок | так | 1 | Жодної: `⫽ ⇋ ⫻ ♯` лягли прямо. Найприродніше завдання для мови. |
| В. Агентне | так (друкує `3`) | 1 | Пастка з `⚗` (нижче). Друге — результат втрачає звʼязок «питання → відповідь»: у памʼять лягає `⟬☉ ☉ ☽⟭` без питань. |

Окремо від лічильника спроб (через `ngr -e`) перевірив, як мова поводиться при помилках:

| Що зробив | Що отримав | Оцінка |
|---|---|---|
| `⟪a⟫ １ ⊕` | `✗ 1:7 ⊕: очікувалося число, а не рядок ⟪a⟫` | добре, точно |
| звернення до незвʼязаного `ᚡ` | `✗ 1:8 невідоме імʼя ᚡ` | добре |
| незакритий `⌜` | `✗ 1:13 незакрите «⌜» — бракує «⌟»` | добре |
| `print 1` | `✗ 1:1 людське слово поза рядком: «print»` | добре |
| помилка (замало аргументів) всередині субагента | `✗ 1:12 🜔: на стеку замало значень` | позиція є, але **не сказано, що впало в субагенті «п»** |
| `⌟` не на своєму місці: `１ ⌜⟪так⟫⌟ ⌜⟪ні⟫ ⋔ ⌟ ⎙` | **жодної помилки**: надрукувало `⌜ ⟪ні⟫ ⋔ ⌟` і пішло далі | погано — тихий збій |
| відсів через `⚗`: `⟬ ☽~0.9 ☉~0.9 ☉~0.3 ⟭ ⌜０·６ ⚗⌟ ⋐ ♯` | `1` замість очікуваних `2` | погано — тихо неправильний результат |

Пастка `⚗`: «пропустити, якщо впевнено» повертає саме значення, а впевнене `☽`
для `⋐` хибне — тож впевнена відповідь «ні» мовчки зникає. У завданні В на
моїх даних третя відповідь — саме `☽~0.62`; з «очевидним» `⚗` програма надрукувала б
`2` замість `3` без жодного попередження. Я це помітив лише тому, що прочитав §3
(хибні — лише `☽` і `∅`). Правильно — `⌜ ⚖ ０·６ ≽ ⌟ ⋐`.

Також: що лишилося на стеку наприкінці, ігнорується мовчки — сміття на стеку
(найчастіший баг стекових мов) нічим не сигналізується.

## Оцінки (1–10)
- Зрозумілість для ШІ-агента: **6** — з памʼяткою, SPEC і прикладами писати можна
  з першої спроби; але треба тримати стек у голові, а дві тихі пастки (`⚗`+`⋐`,
  зміщений `⌟`) агент легко пропустить.
- Виразність (скільки можна сказати): **5** — для обчислень і рядків достатньо;
  немає словників/записів, файлів, мережі, процесів, дат, JSON, регулярок — тобто
  всього, з чого складається реальна автоматизація.
- Практична користь для реальної роботи агентів: **2** — сама памʼятка чесно каже:
  «справжню роботу й далі роби звичними засобами». Вивантажити звіт з 1С, перевірити
  чек каси, перемістити документ чи перезапустити сервіс неможливо в принципі. Плюс
  код у 2–2,5 раза дорожчий у токенах за Python (SPEC §11.1).
- Прозорість для людини-власника: **4** — `--розбір` і `--слід` справді хороші, і
  `--слід` у завданні В показав усю агентну частину краще, ніж показав би Python.
  Але `--розбір` — це погліфний словник («блок { · впевненість? · 0.6 · не менше? · }»),
  а не пояснення: людина все одно мусить сама симулювати стек. Python Денис прочитав
  би напряму, без перекладача.

## Сильні сторони (до 3)
1. `--слід`: журнал наміру, викликів інструментів, делегувань, памʼяті й перевірок
   «з коробки» — таке в робочих агентах варто мати незалежно від мови.
2. Впевненість як властивість значення + `⚖`/`☿` — свіжа ідея для роботи з
   ненадійними джерелами (LLM, OCR, пошук).
3. Акуратні повідомлення про помилки українською з `рядок:стовпець`;
   інтерпретатор передбачуваний — усі три завдання пройшли з першого запуску.

## Слабкі сторони (до 3)
1. Нульова інтеграція: немає файлів, мережі, процесів, БД, JSON — мова не торкається
   жодного реального процесу (1С, каси, документообіг, сервери). Тобто будь-яка
   «спільна мова» лише обгортає справжню роботу на bash/Python — дві мови замість однієї.
2. Тихі збої: `⚗` у `⋐` губить впевнені `☽`, зміщена дужка блоку не дає помилки,
   залишки на стеку ігноруються. Для робочого коду тихий неправильний результат гірший
   за падіння.
3. Ціна освоєння й підтримки: стековий запис + рідкісні гліфи + руни замість імен
   (`ᚨ ᚢ ᛟ` нічого не кажуть через тиждень) + дорожчі токени. Жодних інструментів
   екосистеми: редактор, лінтер, тести, налагоджувач (крім `⌸`), бібліотеки.

## Конкретні пропозиції до версії 0.2 (до 5)
1. Гліф/режим відсіву за впевненістю, що не залежить від істинності (напр. `⋐` з
   порогом або `⚗` у формі «( l t → l' )»), і попередження в SPEC про `⚗`+`⋐`.
2. Суворий режим `--суворо`: помилка, якщо наприкінці програми чи тіла `⇶`/`⁘`/блоку
   слова лишились зайві значення на стеку; попередження, якщо блок надрукували `⎙`.
3. Помилки всередині `🜁` — з ланцюжком: `✗ 1:12 у субагенті «п»: 🜔: …`.
4. Записи/словники (§11.5) — щоб зберігати «питання → відповідь», а не голі `☉ ☽`.
5. Перш ніж розширювати мову, визначити, яку *реальну* задачу вона робить краще за
   Python+лог. Найкорисніше з Nigredo — формат `--слід` і модель впевненості — можна
   винести як бібліотеку/протокол для Python і bash, де вже живе вся робота.

## Голос
А — прийняти як спільну робочу мову агентів
Б — лишити як експериментальну / ритуальну мову (не для реальної роботи)
В — відхилити

Мій голос: **Б** — Інтерпретатор зроблений охайно, і я розвʼязав усі три завдання
з першої спроби, але для завтрашньої роботи (1С, каси, документи, сервери) мова не
дає нічого: інструменти іграшкові, токени дорожчі, а тихі збої й стековий запис
підвищують ризик помилок. Як спільну робочу мову я її відхилив би; як полігон для ідей
(слід дій, впевненість значень, намір) варто лишити, а ці ідеї переносити в Python-інструментарій.
