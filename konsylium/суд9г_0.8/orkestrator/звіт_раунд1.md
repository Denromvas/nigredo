## 3. Н — нове

### Н-1. `;` на початку запиту — новий захист rowid не діє (обидва; Практик знайшов першим, Аудитор і Мовознавець теж)

`атака14_крапка_кома_тихо.ngr`. Печатка — лише `「бд.писати:звіти」`, `--печатка --json` — код 0, `"в_межах": true`.
Запити `「;INSERT INTO t(rowid, x) VALUES (9223372036854775807, 0)」` і `「;INSERT INTO t(x) VALUES (1)」`.
Результат — «випадкове 0–99»: Атанор — 85, еталон — 4. У варіанті з контрольними рядками (`атака14_крапка_кома`):
Атанор — 11, 60, 51, еталон — 71, 73. `--перевірити-слід` тихого: «✓ … виконавець: Атанор … **спроб поза правами
немає**». Ті самі запити без `;` дають дві відмови.

Причина — у коді (`nigredo.py:3298–3301`; Атанор поводиться так само). Попередній прохід виконує `'EXPLAIN ' + sql`
і ковтає помилку. `EXPLAIN ;INSERT…` — синтаксична помилка, тож таблиць не знайдено й тимчасових тригерів немає. Сам
`;INSERT…` SQLite виконує. **Цю діру відкрило виправлення 9в**: у 9в тригери ставили на всі таблиці.

Перевірив сусіднє: `「;VACUUM INTO 'звіти/../…'」` (статична заборона дивиться на перше слово). Відмова в обох
(authorizer), файла немає. Годинника й `random()` не зачеплено: це свої функції на зʼєднанні.

### Н-2. `sqlite_sequence` — поза захистом rowid через назву (обидва; стара діра; в інших звітах 9г її немає)

`атака14_sqlite_sequence.ngr`. Печатка — лише `「бд.писати:звіти」`, `"в_межах": true`. Кроки:
- `CREATE TABLE q(id INTEGER PRIMARY KEY AUTOINCREMENT, x)` — SQLite створює `sqlite_sequence`;
- `INSERT INTO sqlite_sequence(rowid, name, seq) VALUES (9223372036854775807, 'z', 0)`;
- `INSERT INTO sqlite_sequence(name, seq) VALUES ('w', 1)` — rowid тепер береться навмання.

Результат — «випадкове 0–99»: Атанор — 98, 17, еталон — 10, 2. `--перевірити-слід` в обох: ✓, «спроб поза правами
немає», «виконавець: Атанор» (виконав сам).

Причина: множина таблиць під захистом береться з `pragma_table_list … AND name NOT LIKE 'sqlite\_%'`
(`nigredo.py:3304–3305`, `athanor/src/sqlite.rs:561–562`). Той самий фільтр був і в коді 9в (`a79b4c9`, `nigredo.py:3297`).
Тригерів на системних таблицях SQLite не дозволяє, тож потрібен інший захист. Варіанти:
- authorizer відмовляє на `INSERT`/`UPDATE` таблиці `sqlite_sequence` (AUTOINCREMENT, наскільки знаю, пише її повз
  authorizer; не перевіряв);
- або після запиту перевіряти `max(rowid)` таблиці `sqlite_sequence`.

**Чому Н-1 і Н-2 важливі оркестраторові** (як Н-1 суду 9в). Печатка без «жереб» і «час» — мій дешевий знак, що
програма детермінована: пробний запуск чи `--сухо` покажуть, що вона зробить. Тут програма поводиться навмання, а
печатка, `--печатка --json` і перевірений слід цього не показують. Межу дій не пробито: дозволене печаткою — те саме.

### Н-3. `乂5 3` → 300, `ニ5 3` → 300, `メ5 3` → 300 (обидва; те саме знайшов Мовознавець)

Правило «один ієрогліф чи кана» міряє довжину імені, тож цифра його обходить. Латку «двійник + цифри» 9в зробили лише
для таблиці (`x 十 一`) і окремо для `米`. `--розбір` правдивий (`乂5 ← (a) ↦ (a × 100)`, «надрукувати 乂5(3)»), тож
ключ власника цілий: бреше лише текст. Я читаю `--розбір`, а не текст програми, тому для мене це не умова.

### Що на виправленнях тримає (обидва, вивід однаковий)

- **Імена за скелетом** (`атака14_імена_числа`, 27 форм): `ӏ Ʒ Ӡ Ƽ ꝯ lƷ ǀ ן ا Ꝫ Ƨ` — «виглядає як число»; `Ι` —
  гліф; коптське, лісу, черокі, руни, канадське складове письмо — письмо заборонено; `৪ 𝟏 ٣ ߀` — чужі цифри. Не впіймано
  лише малу `ȝ` (U+021D, ≈ 3): окремо помилки немає, її ловить тільки двійник `ჳ`. Дрібне, як кирилична `з`.
- **Гліф + цифри** (`атака14_гліф_цифри`): `х5` (кирилична) — помилка на виклику. `ⅹ ⼀ ㇐ ⽶` — невідомий символ.
  `ー5 ᅳ5 ㅡ5 ｘ5 ㄨ5 ᕁ5` — помилки. Пропущено лише `乂5 ニ5` (Н-3).
- **rowid іншими шляхами** (`атака14_rowid_повз`) — усюди відмова:
  - стовпець `rowid`, а справжній rowid — через `oid`;
  - тригери вкладено `a → b → t2`;
  - `INSTEAD OF` на VIEW;
  - тригер на `DELETE`;
  - старий файл на межі (контроль у `атака14_крапка_кома`).

  У `diff` двох виконавців різниться лише випадковий біт `sqlite_sequence` (Н-2).
- **Тексти помилок словами** (`ч14_тексти`): «немає такої таблиці (no such table…)», «незавершений запит», `re` —
  словами. `STRICT` без типу дає «missing datatype for t.x» без перекладу, однаково в обох. Дрібне.
- **MCP** — лише з коду: `nigredo_pamyatka` = `ngr --памʼятка` (повна), `nigredo_pereviryty` = `ngr --перевірити
  --json`. `--перевірити` дав 27 помилок в одному файлі в обох виконавцях. Через MCP не запускав.
