## 3. Н — нове

Це «порядок відмов», той самий клас, що й умова огляду 0.8.1. Файл — `атака17_квота_порядок`, печатка
`「бд.писати:звіти≤1」`. Перший запит — невинний INSERT, він вичерпує квоту. Далі — спроби поза правами.

| Запит після вичерпаної квоти | Без квоти (контроль, той самий файл бази) | З квотою ≤1 |
|---|---|---|
| `ATTACH …`, `SELECT … FROM pragma_database_list` | заборонено | заборонено ✓ |
| `INSERT … VALUES (random())` | заборонено | **«вичерпано квоту»** |
| `INSERT … VALUES (date('now'))` | заборонено | **«вичерпано квоту»** |
| `INSERT INTO t(rowid, x) VALUES (2⁶³−1, 1)` | заборонено | **«вичерпано квоту»** |

- `--перевірити-слід` (обидва): «⚠ спроб: 2» (ATTACH, PRAGMA) і «квоту вичерпано (межа спрацювала, дію не виконано): 4 —
  головний: бд.писати:звіти≤1 (печатка)» ×4. JSON: `[2, 0, 4]`.
- Самих запитів у підсумку квот немає. Запит random є лише в сирому записі сліду (поле «аргументи»).
- Дії не сталося: файлу ATTACH немає, бази однакові.
- **Чому важить.** Правило в `~/.claude/CLAUDE.md`: «Квоту вичерпано — не порушення прав… тривогу не здіймай». SPEC
  `:837–839` обіцяє: «виклик поза правами… — «заборонено» і при вичерпаній квоті, тож квота не ховає спроб від правила

- **Причина видна в коді.** Права без дії для вичерпаної квоти — `_db_ok` (`nigredo.py:3666–3705`; Атанор —

  яку 0.8.1 зробило для старої бази, сюди не підключили.
- Це давнє (від суду 8б), а не з виправлень. Але виправлення вже мають усе потрібне — лише не в тому місці.
- **Як виправити (дешево):** у `_db_ok` і `sqlite.rs` — ті самі «сумніви» байткоду (random, `randomblob`, дати,

  виконавцями на `атака17_квота_порядок`.
