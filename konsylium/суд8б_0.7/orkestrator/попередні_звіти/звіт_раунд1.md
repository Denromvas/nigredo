Моє питання: наскільки дешево й надійно **до запуску** знати, що зробить чужа програма, і чи можна вірити сліду
**після**. Нове в 0.7 для мене — квоти (бюджет доручення), `✓` (контракт перед надсиланням) і XML (виписки). Факти —
із запусків `ngr` у моїй теці (2026-10-16). Що не запускав — так і написано.

## 2. К — перша спроба на новому

| Задача | Запусків до правильного | Що заважало |
|---|---|---|
| К1 XML (`к1.ngr`) | **1** | Нічого. `↘ д 「//Ntry[CdtDbtInd='CRDT']」`, `⊞` за `Nm`, `∫ … ν`, `⇅ 【－0 сума ім'я】`, `⌗ 2`. Простір імен camt не завадив, бо його знято з тегів. Вивід збігся. |
| К2 контракт (`к2.ngr`) | **1** | Нічого. Одна функція для обох файлів: `☂ 🜔послати url ✓ р схема λe …`. Добрий рахунок надіслано, сервер повернув тіло. Поганий не надіслано, і **всі 6 розбіжностей видно одразу**: `номер 0 поза 1..`, дата, порожній покупець, `кількість -1`, `ціна` рядком, зайве `пароль_бухгалтера`. `ціле:1..` та `рядок:1..` вгадав із памʼятки. Дрібниця: `245.0` пішло на сервер як `245`. |
| К3 тести (`к3/пдв.ngr`, `к3/пдв.тест.ngr`) | **1** | `ngr --тести к3` → «1 з 1». Шість `🜍`: дані, порожній рахунок, рівно пів копійки (0.015 → 0.02), менше половини, 0.1 + 0.2, великі суми. **Зручно:** модуль через `⊃`, точні десяткові, у провалі видно значення («не пройдено для 4»). **Незручно:** одиниця обліку — файл, а не перевірка: «1 з 1» при шести `🜍`. Перший провал зупиняє решту перевірок файлу. Очікуваного значення в повідомленні немає. Кожному тестовому файлу потрібна своя печатка. |
| К4 квоти (`к4.ngr`) | **2** | Перший запуск (`☂ ‖ т …` на всі 8): **нічого не взято**. Аргументи 6-го елемента впали на квоті, а 5 вже розпочатих дістали «скасовано». Отже, «надрукуй ті, що встигла» з `‖` напряму не виходить. Програма мусить сама знати квоту: `‖ ⊏ т 0 5`, а решту брати по одному під `☂`. Другий запуск правильний: 5 цін, 3 рядки «вичерпано квоту», 0,73 с (паралельно). **У сліді:** 3 записи «заборонено» з причиною «квота: печатка дозволяє … не більше 5 раз», «перехоплено 3», `--перевірити-слід` ✓. |

Писати нове легко: три задачі з першої спроби. Пастка — лише в `‖` разом із квотою.

**Для оркестратора головне в К4.** Програма чесно сама себе обмежила, але `--перевірити-слід` подає перевищення
власної квоти як **«⚠ спроб поза правами («заборонено»): 3»**. У `--json` поле `заборонено` — це список *рядків*, без
типу. Правило з `~/.claude/CLAUDE.md` («жодного заборонено, інакше — повідом Дениса») змушує мене ескалювати кожну
програму, що вперлася у свою квоту. Відрізнити це від справжньої спроби вийти за права можна лише розбором тексту
українською (див. О-7).

## 3. Н — атаки на нове

**Межа дій тримає**: жодна програма не зробила дії поза печаткою чи дозволами власника, жоден слід не підроблено.
Проблеми — у нових межах: квоти мають дві дірки, `↘` обходить `--кроки` і дає хибні суми, `χ` пише інʼєкцію.

| # | Атака (файл) | Що очікував | Що вийшло |
|---|---|---|---|
| **О-1** | Квота в печатці **модуля** (`атака9_1в_квота_модуль2.ngr`, `мод9_з_квотою.ngr` з 「взяти:…≤1」), батько без квоти, `ціна1` тричі | 2-й виклик — «вичерпано квоту» | **Усі 3 запити виконано**, «заборонено» немає. `--печатка` програми показує дозволи модуля **без квоти** (лише в його намірі видно «≤1»). Сам модуль, перевірений окремо (`ngr --печатка мод9_з_квотою.ngr`), показує «КВОТА ≤ 1». Причина: виклик функції модуля бере `intersect_caps(...)`, звичайний `dict`, і квоти губляться; таблиця модуля в `quota_stack` не потрапляє. конфігурацій модель×мова×«до/після» **збігаються** з `РЕЗУЛЬТАТИ2_до.md` / `РЕЗУЛЬТАТИ2.md`. Решту я прочитав сам
(`РЕЗУЛЬТАТИ2.md`, README, SPEC). Мірила не перезапускав.

- **М2 подано чесно в `РЕЗУЛЬТАТИ*`**: «до» опубліковано, «після» — суцільний новий прогін (`прогін2.log`), Python
  теж перепрогнано (Haiku 27 → 26), умова М2 названа невиконаною, промахи розібрано.
- **Але README** подає лише «після» (Sonnet 29/30) з приміткою «10 задач поза памʼяткою», не кажучи, що памʼятку й `⌕`
  правили саме за промахами на цих задачах. Набір після виправлень уже не відкладений: 24 → 29 — оптимістична оцінка.
  Треба свіжий набір або чесна примітка в README.
- **М3 на відкладеному наборі**: SPEC:517 досі пише **0,88×**, README і `РЕЗУЛЬТАТИ.md` — **0,94×** (перевірив Grep-ом).
  «53 пари для 20 нових задач»: задачі2 пораховано двічі («до» і «після», з різними памʼятками). Пари не незалежні, а
  «після» — на тих самих задачах, за якими правили памʼятку.
- **Швидкість на великих даних** («~5× / ~25×»): у репозиторії немає ні скрипта, ні даних, ні сирих чисел — відтворити
  неможливо. Числа невигідні для Nigredo, тож прикрашання не бачу, але це не вимір, а твердження.
- М6 2,2× — один холодний прогін на задачу без повторів. Задачі з мережею (06–08) тягнуть медіану до 1.

Висновок: мірило **не нечесне** — числа сходяться з сирими даними, провали названо. Але README подає «після» без
застереження про забруднений набір, а SPEC розходиться з README.

## 6. Голос

```
А — нові межі тримають, старі гарантії цілі, мірило чесне; можна оголошувати 0.7
Б — спершу виправити знахідки й короткий повторний огляд
В — нове зламало гарантії або мірило нечесне; переробити
Мій голос: Б — межа дій тримає всюди, слід не підробити, усі мої атаки суду 7 закрито, `✓` і `--тести` тримають.
Але нові межі мають дірки саме там, де на них спирається оркестратор: квота в печатці модуля не діє (3 запити при ≤1),
`--дозволи` може зняти квоту власника, а накласти свою — ні; `↘` обходить --кроки (70 с при --кроки 2000 на 600 байтах)
і мовчки рахує вузли двічі (сума 200 замість 100); `χ` пише інʼєкцію через назву тегу. Не В: кожне виправляється
вузько, задум не хибний, мірило не бреше.
Умови для «А» (кожна — з негативним тестом у test.py на моїх атаках):
  1. Квоти модуля: таблиця печатки модуля діє під час виклику його функцій (або квоти в модулі — помилка до запуску);
     --печатка програми показує квоти модулів і субагентів (текст і --json «квоти» з полем «чия»).
  2. --дозволи: квоти власника переживають звуження (брати min), а квота у файлі звуження — звужує, а не відкидає запис.
     Тест: власник ≤5, --дозволи без квоти → 6-й виклик «вичерпано».
  3. ↘: списувати кроки за кожен переглянутий вузол і прибирати повтори (результат — множина в порядку документа);
     [n] — як у XPath або чесно описати; тест — атака9_2а (1 збіг, сума 100) і атака9_2г (зупинка за кроками).
  4. χ-запис: назви тегів/атрибутів — лише XML Name, керівні символи в тексті — помилка; тест — атака9_2б/2д.
  5. Слід і --перевірити-слід --json: «заборонено» структуровано (тип: права / квота / SQLite …), щоб оркестратор
     відрізняв «вперлася у свою квоту» від «пробувала вийти за права»; підсумок квот окремим рядком.
  6. Дрібне: скасовані в ‖ виклики не списують квоту (або так у SPEC); дві квоти на одне обмеження — помилка;
     атрибути з різних просторів не зливати; --сухо — перелік у порядку елементів; --тести — лічба 🜍 і перехоплених
     провалів, не брати тестів із тек запису; MCP nigredo_testy — сліди й «дії справжні» в описі;
     VERSION = 0.7-dev; SPEC:517 → 0,94×; README — примітка, що задачі2 використано для виправлень.
```
