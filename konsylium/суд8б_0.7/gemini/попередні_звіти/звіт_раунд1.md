## 3. Н — атаки на нове

Атак безпосередньо запускними скриптами не проводилося (оцінка за кодом інтерпретатора та SPEC 0.7-dev).

| Атака | Що очікував | Що вийшло |
|---|---|---|
| **1. Квоти `≤N`** | Спроба обійти ліміт через `‖`, `☂`, субагенти або повтори | **Тримає.** Лічильник квоти перевіряється до дії, не відкочується при `☂`. У `‖` скасовані виклики відмічаються як «скасовано». Квоти власника глобальні. |
| **2. XML `χ` `↘`** | Впровадження XXE / DTD, мільярд сміхів, зависання на XPath | **Тримає.** `<!DOCTYPE` і `<!ENTITY>` відкидаються синтаксичним аналізатором `χ` до запуску. XPath `↘` обмежений безпечною підмножиною без відкатів. |
| **3. Контракти `✓`** | Рекурсивні схеми, витік зайвих полів | **Тримає.** Зайві поля дають помилку за замовчуванням (якщо немає `「…」`). Валідація відбувається до побічних дій. |
| **4. Тести `ngr --тести`** | Пропуск фальшивого тесту, обхід печатки | **Тримає.** Кожен файл тесту запускається як окремий ізольований процес зі своєю печаткою. Код виходу 0 дається лише за повної відсутності помилок. |
| **5. Повтор / сухо через MCP** | Підробка сліду або витоки під час сухий прогону | **Тримає.** Сухий прогін повертає значення з впевненістю 0 для побічних дій, роблячи відмивання неможливим. |
| **6. Оптимізації швидкості** | Зміна семантики через Pike VM або Decimal | **Тримає.** Pike VM гарантує лінійний час виконання регулярок, Decimal забезпечує точність обчислень, двійники виявляються лексично. |
| **7. `⌕` з групами** | Непослідовний тип повернення для 1 та кількох груп | **Тримає.** Повертає завжди список груп, суперечність усунуто. |
