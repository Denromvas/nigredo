**Межу дій (печатка ∪ дозволи власника) знову не пробив ніде.** Знайшов один код 4 з даних, одну неправду ключа

### Н-1. Код 4 з даних у `↘`: `]` у значенні умови — СЕРЙОЗНЕ

`атака10_шлях_код4.ngr`:
```
← назва 「ТОВ [Ромашка]」
» ☂ ρ ↘ д 〔//Ntry[Nm='{назва}']/Amt〕 λпом …
```
→ `✗ внутрішня помилка інтерпретатора Nigredo (AttributeError: 'NoneType' object has no attribute 'group')`.
`☂` не спрацював, «далі живий» не надруковано. `--перевірити` каже «помилок не знайдено». `--перевірити-слід` —
«⚠ ВНУТРІШНЯ ПОМИЛКА (код 4)».

Причина (код `xml_path`): граматика `cond_re` (р. 2349) пускає `]` усередині лапок, а умови потім ріжуться
регуляркою `\[([^\]]*)\]` (р. 2364) по першій `]`. Тоді `ok()` (р. 2397) отримує `Nm='ТОВ [Ромашка` і `mm = None`.
Шлях, складений з назви контрагента, — звичайна річ для ніші «1С/виписки». Назви з дужками («ТОВ "Ромашка" [філія]»)
теж трапляються. Тобто це той самий клас «код 4 від даних повз `☂`», який суд 8 вимагав прибрати, на іншому вході.
Виправлення — одна стрічка: брати умови тією самою `cond_re` (`findall`), а не `[^\]]*`, і додати негативний тест.

Решта граматики `↘` (`атака10_шлях`, 27 шляхів) **тримає**. Подвійні лапки, пробіли в умові, два предикати,
`[n]` після умови, `[0]`, величезне `n`, `/Document/…/Ntry[5]`, префікс у шляху, `//Amt[2]` → `【】`,
`//Stmt//Amt[1]` → 5 — усе як у XPath. А `[-1]`, `[1.5]`, `//@*`, `*[@Ccy]`, шлях у предикаті, `///`, кінцевий
`/`, `''` у значенні, `*=` і табуляція дають помилку «поза підмножиною».

### Н-2. Вичерпана квота ховає спроби поза правами — неправда ключа власника

`атака10_квота_ховає2.ngr` (печатка `взяти:127.0.0.1:28709≤1`, `читати:дані≤1`) спершу чесно використовує обидві
квоти, а потім пробує:
- `http://злодій:пароль@127.0.0.1:28709/…` (логін в адресі);
- `дані/../к1.ngr` (файл поза текою `дані`).

Обидві спроби дають «вичерпано квоту». У сліді це записано як «квоту вичерпано», а не «заборонено». Контроль
(`атака10_квота_ховає_контроль.ngr`, квота ≤5) на тих самих двох адресах дає «⚠ спроб поза правами: 2».

Причина (код): у `tool_begin` (р. 3133) `check_quota` іде **до** перевірок прав самого інструмента. Крім того,
`quota_covers` для теки (р. 3146–3148) зараховує шлях і від теки квоти, тож `дані/../к1.ngr` «покрито» як
`дані/к1.ngr`, а для хоста логін не перевіряється. Наслідок: програма вичерпує квоту, а далі пробує те, що
заборонено, і `--перевірити-слід` не рахує цього як «заборонено». Правило в `~/.claude/CLAUDE.md` прямо каже:
«Квоту вичерпано — не порушення прав… тривогу не здіймай». Отже агент-перевіряльник промовчить. Дії не
відбувається, межа ціла, але неправдивим стає саме той лічильник, на якому стоїть правило власника.
Виправлення: коли квоту вичерпано, спершу виконати перевірку прав (або в `quota_covers` — ту саму, що й для
дозволу). Дія поза правами — «заборонено», а «квоту вичерпано» лише для дозволеного.

Решта квот **тримає**. `атака10_квоти`: `‖` із 4 при ≤3 падає й повертає квоту, далі 3 запити проходять. Відмова
за правами (чужий порт двічі) квоту повертає, і «намотати» запас нею не можна. Субагент зі своєю ≤1 на кожен запуск,
а батьківська ≤3 рахує все. `атака10_модулі`: квоту модуля спільно рахують прямий виклик, обгортка з іншого модуля
(той самий файл імпортовано вдруге) і субагент. `≤0`, `≤٣`, `≤３` — помилка до запуску. `жереб≤2` діє.

### Н-3. `--сухо`: годинник ДО першої придушеної дії — рішення без ⚠

`атака10_сухо3.ngr`: `🜔час` на початку, далі за парністю секунди або `послати рахунок_поганий.json`, або нічого.
Два сухі прогони тієї самої програми:
- секунда 59 → «1 дій не виконано: мережа.послати …», **без ⚠**;
- секунда 0 → «0 дій не виконано (жодної дії назовні)», **без ⚠**.

Оркестратор, який вирішує за сухим прогоном, отримає «жодної дії назовні», а справжній запуск надішле рахунок із
`пароль_бухгалтера`. SPEC р. 457–458 обіцяє: «рішення за годинником дає ⚠». Для годинника після придушеної дії
це правда (`в_сухо_час`, `атака10_сухо` з відмиванням через `≈` — ⚠ є), для годинника до неї — ні. Печатка при цьому
правдива: `послати` в ній є. Тому це не обхід, а неправда прогнозу. Виправлення: у `--сухо` вважати `час` (і
`оракул`) невідомим завжди, а не лише після придушеної дії. Або хоча б давати ⚠ на кожне рішення, залежне від
годинника, і виправити SPEC.

### Н-5. Дрібне (не блокує)

1. `✓`: перелік не приймає `¯` (`「число:¯1|1」` відкидає ¯1, хоча межі `¯5..5` працюють). Межі для `∅`
   (`「∅:0..1」`) мовчки прийнято, а для `●/○` — «помилка схеми». Два ключі `「…」` у схемі — мовчки діє останній.
2. `χ`-запис: тег `p:Платіж` без простору записується, але назад не читається («unbound prefix»). `\r` у тексті
   після «туди й назад» стає `\n`. SPEC обіцяє, що теги й тексти зберігаються.
3. SQLite: звичайне значення `INSERT … VALUES ('load_extension')` — відмова (фільтр за підрядком, хибна тривога).
4. `‖, елемент №N` — досі з 0 (К4: «№5» — це 6-й елемент). Мовчу третій суд поспіль, тож кажу.
5. `--тести`: тест із печаткою, ширшою за власника (`писати:/tmp`), — ✗ правильно, але з причиною «слід лежить у теці з
   печатки», а не «печатка просить більше». Квоту з `--дозволи` в повідомленні підписано «власник:».
6. `⌕` з буквальною групою — `--перевірити` мовчить (було «бажано» в суді 8).

## 4. Ч — мірило

1. **М2 — тепер чесно.** README подає «до» і «після» в одній клітинці: «Sonnet 29/30, Haiku 24/30 (перший прогін:
   24/30 і 24/30)», Python — «30/30, 26/30 (перший: 30, 27)». Прямо написано, що повтор — «на тих самих задачах…
   тож це не відкладений вимір; ±1–2 з 30 — шум». Саме цього я й вимагав. Закрито.
2. **М3 0,88× — обрахунок чесний, подача в README — ні.**
   - Подвійний облік прибрано: `held_out` пропускає `прогони2_до`. Пари я перерахував сам із сирих файлів (Grep
     `"гаразд"` першої спроби в `прогони/*/` і `прогони2/*/`): з 40 можливих відпало 4, тож **36 збігається**. Число
     не вигадане.
   - Але всі 4 пари, що відпали, — Haiku, і в кожній Nigredo впала з першої спроби (`06_sklad`, `02_vyniatky`,
     `04_intervaly`, `07_konfih`). Відбір прибирає саме ті випадки, де Nigredo важча.
   - Асиметрію підказок не вирівняно: памʼятка радить короткі імена, підказка Python — ні. Обидва застереження чесно
     стоять у `bench/РЕЗУЛЬТАТИ.md`. **У README їх немає.** Там жирне «**0,88×** … для 20 нових задач», хоча 10 із
     цих 20 (`прогони2`) — повтор після виправлень на тих самих задачах (у рядку М2 це сказано, у рядку М3 — ні).
     Чесно було б дописати в README ті самі три застереження одним рядком. Це не фальш, а вибір, що показати на
     вітрині.
3. **Швидкість — чесно.** `bench/великі/міряти.py` міряє процесорний час разом із запуском, бере найкращий із 3 і
   звіряє, чи вивід однаковий. Програми — звичайні однорядкові. Nigredo-частину я заміряв сам: `арифм.ngr` — 0,8 с,
   результат 400001 правильний. Python запустити не можу, тож співвідношення ~5×/~30× не перевіряв. Помітно, що
   число в README **погіршилось** (у суді 8 було ~25×): автор не прикрашає.
