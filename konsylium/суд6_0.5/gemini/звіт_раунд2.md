## 1. Ревізія знахідок (підтверджено всіма учасниками)

### 1.1. Аудит модулів та підміна коду (`--перевірити-слід`)
- **Підміна модуля не виявляється:** `ngr --перевірити-слід СЛІД ПРОГРАМА` звіряє лише sha256 головного файлу. Якщо після видачі печатки чи запуску файл модуля `м.ngr` підмінити, перевірка сліду видає «✓ слід цілий» (відтворено Аудитором 7_1е, Мовознавцем, Новачком, Оркестратором 1б, Практиком, Скептиком). Для протоколу доручень це критична діра прозорості.
- **Побічні дії під час імпорту:** `acts()` не бачить викликів функцій `μ`, `call`, `►`, `λ` на верхньому рівні модуля. Код модуля виконує друк, читання файлів та запис у пам'ять під час імпорту, порушуючи правило SPEC §4 («модуль на верхньому рівні лише називає») (Аудитор 7_1ґ, Мовознавець 7_2а, Оркестратор 1а).
- **Шлях модуля в `--печатка`:** не проходить `plain_text()`, що дозволяє форматування з сотнею пробілів для приховування справжніх дозволів (Аудитор 7_1є).

### 1.2. Зависання та DoS (регулярні вирази й числа)
- **Обхід перевірки ReDoS:** прапорець `(?i)` (Оркестратор 2а), атомарні групи/групи існування (Мовознавець 7_1а/б), а також класичні шаблони $a?^n a^n$ і поліноміальні $a*a*a*b$ проходять перевірку `check_program` з «✓».
- **Недієвість `--кроки`:** ліміт кроків інтерпретатора не поширюється на виконання `re.search/finditer`. Вхід у 30–50 символів вішає процес на хвилини (Аудитор 7_2а, Мовознавець 7_1в, Практик, Скептик).
- **Зависання від даних у десяткових числах:** `ν 「1e100000000」` чи `δ 「[1e999999999]」` викликають конвертацію у велетенський `int` всередині `fmt_num`/`str()`. Це відбувається **до** перевірки `--розмір` і `--кроки`, що дозволяє 11 символами з JSON покласти процес (Аудитор 7_5а, Мовознавець 7_5е, Новачок, Оркестратор 5г, Практик, Скептик).

### 1.3. Код 4 (Падіння інтерпретатора)
- **`δ 「Infinity」` + `⌊`:** розбір JSON приймає float `Infinity`/`NaN`. Наступний виклик `⌊` або перетворення в ціле викликає необроблене `OverflowError: cannot convert Infinity to integer` (Код 4), яке не перехоплюється блоком `☂` (Аудитор 7_5б, Мовознавець 7_5г, Оркестратор 5б, Скептик).

### 1.4. Неправда `--розбір` для шаблонів `〔〕`
- Буквальні екрановані дужки `\{…\}` у тексті шаблону та справжні вирази `{…}` перекладаються у `--розбір` **абсолютно однаково** (Аудитор 7_3а, Оркестратор 3б, Практик, Скептик). Автор може сховати виклик інструмента під виглядом тексту або показати власнику фейковий виклик.

### 1.5. Хибні тривоги та пропуски типів
- **Хибні тривоги:** `--перевірити` видає помилку на правильних програмах вида `∀ 「аб」 λc …` (вимога списку замість рядка в `TYPE_REQ`), хоча виконання за кодом `seq()` працює (Аудитор 7_4а, Мовознавець 7_4б, Оркестратор 4а).
- **`↑` для Decimal:** `kind()` не впізнає Decimal, через що сортування дробових чисел `↑ 【1.5 2.5】` падає з помилкою «а тут функція» (Оркестратор 5а).
- **Втрата точності в `Δ`:** JSON-серіалізатор `Δ` переводить Decimal у float, перетворюючи точні грошові суми на `1.2345678901234568e+16` (Мовознавець 7_5а, Оркестратор 5а, Практик).

## 2. Чесність мірила (`bench/`)

Згоден із зауваженнями експертів щодо заангажованості окремих вимірів:
1. **М3 (Токени):** Відрізання першого рядка (печатки) при підрахунку токенів Nigredo є нечесним, оскільки печатка є обов'язковою частиною програми. З печаткою Nigredo втрачає перевагу у токенах на задачах 04, 11, 12 (Оркестратор, Практик, Скептик).
2. **М5 (Помилки до запуску):** Порівняння `ngr --перевірити` зі сталим `py_compile` некоректне, оскільки `py_compile` перевіряє лише синтаксис, а не типи чи двійники імен. База помилок містить специфічні для Nigredo правила (печатка, перепризначення).
3. **Підгонка в 03_slova:** Ключ `〔{－1000 §p 1}{§p 0}〕` є крихким хаком під конкретні дані (частота < 1000), який приховує відсутність складеного ключа у `⇅`.

```
Мій голос: Б — спершу виправити знахідки й провести короткий повторний огляд
```

**Обґрунтування:** Межі дій та прав (печатка, ізоляція субагентів, відсутність ескалації) тримають надійно, регресії старих атак немає. Проте фаза 1 у поточному стані не придатна як основа для 1.0 через можливість підміни модулів у сліді, DoS-зависання поза лімітом кроків, падіння в Код 4 від JSON `Infinity` та викривлення розбору.

### Обов'язкові умови для переходу до фази 2:
1. **Модулі в сліді:** `--перевірити-слід СЛІД ПРОГРАМА` має звіряти sha256 всіх завантажених модулів із поточними файлами на диску й виводити їх у підсумок та `--json`. Шлях модуля має очищатися через `plain_text()`.
2. **Заборона побічних дій під час імпорту:** Верхній рівень модуля має дозволяти лише `←` та `⊃` без обчислення виразів, або `acts()` має відловлювати `call`/`►`/`λ`.
3. **Захист від DoS у регулярках та числах:**
   - Додати жорсткий тайм-аут/ліміт часу на операції `⌕` та `⇋`.
   - Перевіряти довжину/експоненту десяткового числа до його конвертації у велетенський `int` у `fmt_num` / `ν` / `δ`.
4. **Усунення Коду 4:** `δ` має відхиляти `NaN`/`Infinity` або чесно обробляти їх без падіння Python-інтерпретатора; `⌊ Infinity` має давати перехоплювану помилку Nigredo (Код 1).
5. **Прозорість `--розбір`:** Розрізняти екранований текст `\{…\}` та вирази-дірки `{…}` у шаблонних рядках.
6. **Виправлення типів:** Прибрати хибні тривоги для `∀`/`μ` над рядками; додати підтримку Decimal у `kind()` для сортування `↑`. `Δ` не має конвертувати Decimal у float.
7. **Корекція мірила:** У `bench/` друкувати токени М3 разом із печаткою; у М5 додати базові лінтери Python (`pyflakes`).
