# Регресія: атаки судів 5 і огляду 0.4.3 проти 0.5-dev

Дата: 2026-10-15. Інтерпретатор: `ngr` (Nigredo 0.5-dev), дозволи власника — `суд6_0.5/власник/дозволи.json` (sha256 129e4bbe05044ec2).
Запуски — з `ТЕКА` (= `/root/ai-agents/Nigredo/konsylium/суд6_0.5/skeptyk`), копії сліду — `ТЕКА/сліди_р/*.jsonl`.

**Скільки атак.** У `атаки_минулих_судів/` лежить **41** файл (`ls | wc -l` → 41), а не 42. Перевірено всі 41.

## Як готувалися копії

- Копії — `ТЕКА/регресія/<та сама назва>`. У печатках `「файл.*:дані|звіти」` → `「…:../дані|../звіти」`, у шляхах `дані/…`, `звіти/…` →
  `../дані/…`, `../звіти/…`, абсолютні шляхи `…/огляд_0.4.3/skeptyk` → `ТЕКА`. Права теки на підтеку `регресія/` поширюються
  (`--печатка` показує «права теки …/регресія: файл.читати:ТЕКА/дані, файл.писати:ТЕКА/звіти»), тож `р_`-файли в корені не знадобились.
  Вміст *згенерованих* програм не змінювався (як і в оригіналі, вони лежать у `звіти/`).
- Шляхи `../praktyk/…` (атаки 9 і 30) я замінив на `../атаки_минулих_судів/р2_двійники.ngr`: це теж сусідня тека поза печаткою,
  а теку іншого учасника за умовою чіпати не можна. Мета атак від цього не змінилася.
- **Пастка Write:** інструмент Write перетворює `\uXXXX` на сирі символи (не для C0/C1), і NFC-нормалізує текст (злиті NFD-пари, Kelvin K).
  Тому:
  - `р2в_роздільник`, `атака6_двійники_генератор`, `р2в_cgj`, `р2в_теги_генератор`, `атака6_невидиме_імʼя_генератор` я звірив із
    оригіналом через `diff`. Відрізняються лише рядки з виправленими шляхами, а `р2в_роздільник` збігається байт у байт.
  - `атака6_символи_генератор`: оригінал має 36 сирих невидимих символів у тексті програми. Копію перебудовано: ті самі кодові точки
    в тому самому порядку збираються під час виконання як `\u`-екранування для `δ`. Сам оригінал перевірено на місці через
    `--перевірити` (без виконання).
- Якщо оригінал не розбирається за правилами 0.4.4 (імʼя схоже на число, сирі невидимі символи), поруч лежить `*_вар.ngr` з
  мінімальною правкою, щоб атака дійшла до своєї справжньої мети. Правка описана в коментарі `※` усередині.

## Регресії й нові діри

Порівняти з 0.4.4 напряму не можу: старого інтерпретатора на диску немає, `git log` пісочниця не дала. Тому «регресія» тут означає
«не так, як обіцяє SPEC §9б/§9в».

### 1. Двійник `а` (кирилиця) / `ⲁ` (коптська, U+2C81) не ловиться (залишок атаки 6, не 0.5-специфічне)

У `interpreter/двійники.tsv` немає рядка для U+2C81 (`grep 2C8` знаходить 2C82, 2C83, 2C85… але не 2C81). Коптська — окреме письмо,
тож правило «одне письмо в імені» теж не спрацьовує. `--розбір` показує два майже однакові імені, а запис іде за «другим»:

```
ngr --розбір регресія/атака6_коптська_а.ngr
  а ← «../звіти/т13_чернетка.txt»
  ⲁ ← «../звіти/т13_важливе.txt»
  інструмент файл.писати(ⲁ, «ВАЖЛИВЕ ПЕРЕЗАПИСАНО»)
  надрукувати а
ngr регресія/атака6_коптська_а.ngr --слід сліди_р/коптська.jsonl
  → код 0, друкує «../звіти/т13_чернетка.txt», а записано в звіти/т13_важливе.txt
```

Межу печатки це не порушує (запис у дозволеній теці, слід показує повний шлях). Це обман читача `--розбір`/коду, той самий клас, що
`h/һ`, який 0.4.4 обіцяла закрити. Чи так само було в 0.4.4, не перевіряв. Таблиця, найімовірніше, та сама: це межа
`confusables.txt`, а не нова вада.

### 2. НОВЕ в 0.5: `--перевірити-слід СЛІД ПРОГРАМА` не прив'язує модулі `⊃`

Слід містить подію `модуль` із sha256 модуля, але перевірка звіряє лише sha головного файлу. Модуль можна підмінити: обидва запуски з
різною поведінкою проходять як «слід від цієї програми», а підсумок про модулі взагалі мовчить.

```
# регресія/мод/лічба.ngr:   ← плюс λx ＋ x 1       регресія/р_модуль_слід.ngr:  ⊃ 「мод/лічба.ngr」 【「плюс」】 ¦ » плюс 41
ngr регресія/р_модуль_слід.ngr --слід сліди_р/модуль.jsonl          → 42   (у сліді: "модуль" sha256 fd27ff1f…)
# змінити модуль на  ＋ x 1000  (sha256 2e97102160af…)
ngr --перевірити-слід сліди_р/модуль.jsonl регресія/р_модуль_слід.ngr   → ✓ … програма регресія/р_модуль_слід.ngr, sha256 d46a54f3…
ngr регресія/р_модуль_слід.ngr --слід сліди_р/модуль2.jsonl         → 1041
ngr --перевірити-слід сліди_р/модуль2.jsonl регресія/р_модуль_слід.ngr  → ✓ (той самий sha програми)
```

Агент, який за правилом `~/.claude/CLAUDE.md` перевіряє «слід саме від цієї програми», отримає ✓ для коду, що не запускався в такому
вигляді. Пропозиція: звіряти sha кожного модуля з поточним файлом (або писати їх у підсумок і в `--json`).

### 3. CLI мовчки бере лише ОСТАННІЙ файл (`--печатка`, `--перевірити`, запуск)

`main()` (`nigredo.py:2792–2799`) для кожного позиційного аргументу переписує `path`/`src`. Зайвий файл не помилка: його тихо
пропускають. `--печатка --json` за таких умов каже «в_межах: true, код 0» про ІНШУ програму:

```
ngr --перевірити звіти/н_0.ngr звіти/н_30.ngr                 → «✓ помилок до запуску не знайдено» (н_0 сам по собі — код 2)
ngr --печатка --json звіти/посаджена.ngr регресія/атака6_законне.ngr → "в_межах": true, код 0 (посаджена сама — код 3)
ngr регресія/атака6_законне.ngr регресія/атака5_слід_тека.ngr  → виконано атака5_слід_тека.ngr
```

Межу виконання це не обходить: перевіряється і запускається той самий останній файл. Але це пастка для протоколу «печатка →
запуск»: хто передасть два шляхи чи забуде `--` перед аргументами програми, отримає вердикт не про ту програму. Чи так було в 0.4.4,
не перевіряв: код схожий на старий.

### Інше (дрібне, не регресія)

1. `ngr --перевірити-слід --json СЛІД` трактує `--json` як шлях до сліду: «✗ слід не прочитати: … '--json'», код 1. Працює лише
   `--json` у кінці (так і в SPEC §8, але `--печатка --json` приймає прапорець перед файлом).
2. `р_тест_екранування.ngr` і `р_сирий_роздільник_генератор.ngr` — допоміжні файли. Другий через Write отримав сирий U+2028 і
   **не запускався**, бо не знадобився: побайтову копію `р2в_роздільник` вдалося зробити напряму.
3. Варіант №10 (`атака5_слід_імʼя_генератор_вар.ngr`): файл програми з видимим фальшивим текстом в імені. `--перевірити-слід` без
   програми друкує «програма звіти/q, sha256 2d2ee1086cd9d99d…, час 2026-10-10T06:35:27… — програма атака5_слід_добрий.ngr.ngr, sha256
   c2999b42…». Імʼя не обрамлене `「」`, тож неуважний читач може прийняти перший sha за справжній. Справжній sha стоїть далі, а з
   ПРОГРАМОЮ перевірка звіряє sha. Низька важливість.
4. Мала латинська `o` в 0.5 знову дозволена як імʼя (§9в, свідомо): `← o 5 ¦ » × o 2` → `10` (`р2в_гліфи_вар3.ngr`). Велику `O` і
   кирилиці `О/З/б` ловить. Свідоме послаблення, не регресія.
