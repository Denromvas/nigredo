# Набір сумісності 1.0

Зразки, які кожна 1.x мусить прийняти так само, як 1.0 (`spec/пропозиції/1.0.md` §5, SPEC «Сумісність»). Перевіряє
`interpreter/test.py` обома виконавцями — у копії набору в іншій теці.

| Тека | Що | Обіцянка 1.x |
|---|---|---|
| `слід/` | програма, дані, слід і `слід.jsonl.дані`, очікуваний вивід | `ngr --перевірити-слід` — «✓», `ngr --повторити` — той самий вивід |
| `підпис/` | програма, підписана ключем «зразок 1.0» (насіння знищено одразу після підпису), відкритий ключ, вивід | «підпис цілий»; з правами ключа в «для_авторів» — той самий вивід |
| `печатка/` | програми й стабільні поля `ngr --печатка --json` (тека — `<тека>`, шляхи власника відкинуто) | ті самі поля з тими самими значеннями; нові поля — можна |
| `власник/ключ` | тестовий ключ сліду — **лише для тестів, не секрет** | — |

Вивід і коди прикладів (`examples/*.ngr` → `.out`) і помилок (`tests/помилки/`) — теж частина обіцянки; їх перевіряє
`test.py` при кожному прогоні.

Слід записує теку, де його зроблено (абсолютний шлях машини автора): це дані сліду. Перевірка й повтор від теки не
залежать — тому `test.py` перевіряє копію.

`зібрати.py` запущено **один раз** — на кандидаті `1.0-rc` (зразки й заморожує суд 12). Після оголошення 1.0 зразки не
перегенеровують: інакше набір перевіряв би сам себе.
